# F-045 — Conception : colonne « Étiquettes », couleurs d'option, création à la frappe, filtre « contient »

Date : 2026-10-30
Spec : `specs/F-045.md`, validée (`c59d2b0`), lue sur la branche `F-045` (base `a64bf5f`). ADR : amendement F-045 de l'ADR-0016 (proposé). Code lu : `packages/document/src/{table,format-table,document-table,erreurs,index}.ts` sur `main`, et le diff de la branche `F-034` (`4d47cae`) sur `document-table.ts` et `format-table.ts`.

`ARCHITECTURE.md` décrit `main` et n'est pas touché ici : il sera aligné sur le code livré, après le dernier bloc.

## Approche

- Le modèle (`packages/document`) porte tout ce qui touche au format : sixième type `etiquettes`, cellule d'ensemble fusionnée par étiquette, couleur d'option, version 2. La décision et ses raisons sont dans l'amendement F-045 de l'ADR-0016 ; cette note en donne l'interface et le découpage.
- L'écran (`apps/web/src/vues-de-table/`) ajoute l'affichage en pastilles, le champ de saisie à liste, la couleur dans le panneau « Options », les opérateurs de filtre ; les classes vont dans les composants de présentation existants (`interface/composants/Table.tsx`, `table.classes.ts`) : le module des vues n'écrit aucune classe (F-018-AC55).
- **Pas de garde côté serveur (H2 tranchée : non).** Le serveur ne lit ni le document de page ni le document de table (ADR-0013, ADR-0016) ; les versions 2 et 3 du document de page (F-028, F-005) sont passées sans garde serveur. La version d'un document de table ne protège que contre une application ancienne honnête, et elle y suffit : la version et la première colonne `etiquettes` partent dans la même transaction, donc la même mise à jour. Un pair forgé qui retirerait l'entrée `2` de `versions` peut déjà détruire tout contenu de la table qu'il a le droit d'écrire (`editeur`) : la menace est celle des « Conséquences » de l'ADR-0016, inchangée. La spec n'est donc pas retouchée : ni `agent-backend`, ni `reviewer-backend`, ni `reviewer-api`.
- Aucune dépendance nouvelle, aucun paquet nouveau, aucune règle de `.dependency-cruiser.cjs` nouvelle : les règles `document-coeur-pur`, `document-yjs-seulement`, `web-document-par-ses-exports` et `web-src-liste-blanche` couvrent les fichiers touchés.

`couleur` est **optionnelle et absente pour « defaut »**, comme `type?: "table"` de `PageLue` (F-018-AC2) : une option lue sans couleur garde exactement sa forme d'avant, et les tests livrés qui comparent `{ id, libelle }` (`toEqual`) ou qui bâtissent une `TableLue` littérale (F-018, F-019, F-020 : `kanban-ecran.test.tsx` l. 268 et 356, `fonctions.test.ts`, `reglages.test.tsx`, `affichage-fige-vues.test.tsx`, `selecteur.test.tsx`, `composants.test.tsx`) passent sans modification ni erreur de types. « Se lit « defaut » » (F-045-AC5, AC10) se prouve par `couleur === undefined` ; l'écran lit `option.couleur ?? "defaut"`. Le type de la couleur n'est pas exporté : `apps/web` le nomme `NonNullable<OptionLue["couleur"]> | "defaut"`.

Façade `DocumentTable` (signatures existantes inchangées ; quatre opérations ajoutées) :

| Opération                                                    | Effet                                                                                                                                                                    | Refus (codes existants)                                                                                                                                                                          |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `creerColonne(nom, "etiquettes", position?)`                 | colonne et sa carte `options` ; version portée à 2 dans la même transaction si elle est lue inférieure (F-045-AC1, AC11)                                                 | inchangés                                                                                                                                                                                        |
| `ecrireCellule(ligne, colonne, valeur)`                      | colonne `etiquettes` : `valeur` est une liste d'identifiants d'options ou `null` ; la cellule devient exactement cet ensemble ; rien n'est émis s'il est déjà lu (AC2)   | `valeur-non-conforme` (identifiant hors des options lues, doublon, plus de 100, élément non chaîne, liste à une autre colonne, scalaire à celle-ci) ; `ligne-introuvable`, `colonne-introuvable` |
| `ajouterEtiquette(ligne, colonne, option)`                   | ajoute une étiquette ; sans effet ni mise à jour si elle est portée (AC3)                                                                                                | `valeur-non-conforme` (colonne d'un autre type, 101e étiquette) ; `option-introuvable` ; cibles                                                                                                  |
| `retirerEtiquette(ligne, colonne, option)`                   | retire une étiquette ; sans effet si elle est absente (AC3)                                                                                                              | `valeur-non-conforme` (colonne d'un autre type) ; cibles. Une option retirée de la colonne n'est pas un refus : rien à faire                                                                     |
| `colorerOption(colonne, option, couleur)`                    | écrit `couleur` ; rien si elle est déjà lue ; « defaut » s'écrit comme les autres (AC5)                                                                                  | `valeur-non-conforme` (couleur hors palette) ; `colonne-sans-options` ; `option-introuvable`                                                                                                     |
| `creerOptionDansLaCellule(ligne, colonne, libelle, couleur)` | une transaction : l'option (dernière position), sa couleur, puis l'affectation (étiquette ajoutée, ou valeur d'une colonne `selection`) ; rend l'identifiant (AC4, AC16) | tous les contrôles avant la transaction : `libelle-non-admis`, `valeur-non-conforme` (couleur ; cellule déjà à 100), `colonne-sans-options`, cibles : rien n'est créé                            |

- `colonne-sans-options` vaut désormais pour toute colonne qui n'est ni `selection` ni `etiquettes` (`exigerColonneAOptions`) ; son message cesse de dire « colonne de sélection ». `ajouterOption`, `renommerOption`, `deplacerOption`, `retirerOption` acceptent une colonne `etiquettes`.
- `retirerOption` ne touche aucune cellule (drapeau seul) : la lecture écarte l'étiquette (AC6). F-045-AC6 et AC7 (retrait concurrent) en découlent sans écriture de cellule.
- `memeTable` compare aussi `couleur` et les listes de cellule élément par élément (une liste relue est un nouveau tableau) : sans quoi chaque transaction notifierait (F-017-AC9). `ecrireUneCellule` compare par la même égalité.
- `creerLigne(valeurs)` accepte une liste pour une colonne `etiquettes` (mêmes refus) : F-044 s'en sert pour les modèles de ligne.

## Risques

- L'élargissement de `ValeurDeCellule` touche chaque comparaison `===` de valeur dans `apps/web` (sélection courante, mise en évidence, kanban) : la couture AC29 et l'exhaustivité des `switch` sont la parade ; une comparaison oubliée rend une liste toujours « changée » (rendu en trop, pas de perte).
- Une cellule forgée de milliers de clés est lue tronquée à 100 étiquettes, dans l'ordre des options ; son coût de lecture est borné par la taille de message du serveur (`message-trop-grand`).
- Contraste : neuf jetons de texte de plus sur sept surfaces ; si une couleur (marron, gris) ne tient pas 4,5 pour 1 partout, sa primitive est éclaircie, jamais le seuil baissé.
