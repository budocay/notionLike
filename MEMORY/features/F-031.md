## Décisions prises au code

- Vérification de la configuration (ADR-0017, B2) : `apps/server/src/verifier-configuration.ts`, lancée par `docker compose … -f infra/verification-configuration.yml --progress quiet run --rm --no-deps -T serveur node apps/server/src/verifier-configuration.ts`, après un `compose build` visible ; surcharge telle que l'ADR (`base.volumes: !reset []`, `serveur.network_mode: none`, `volumes: !reset {}`). La veille propose aussi `!reset null` sur `base` et `migration` ; la forme de l'ADR, éprouvée en E3, est gardée.
- Ordre de `demarrer` : poste, `preparer`, mot de passe (AC9), ports (AC18), présence du volume notée, `build`, vérification (AC8, AC10), avertissement du mode hôte (AC11), épreuve si le volume existait (AC20), `up -d --wait --build`, `/pret`. Le volume est constaté avant la vérification (veille).
- Création des fichiers : contenu entier dans un temporaire `.env.<aléa>.local` du même dossier, créé sous `set -C`, puis publié par `link` (link(2) : refuse aussi un dossier, à la différence de `ln` qui crée le lien dedans), temporaire retiré sur tous les chemins. Aléa par `od -An -N<n> -tx1 /dev/urandom`.
- Épreuve du mot de passe : `PGPASSWORD` exporté puis `docker compose exec -T -e PGPASSWORD base psql -h base -U notionlike -d notionlike -w -At -c 'select 1'` (règle `scram-sha-256` ; `-h 127.0.0.1` serait en `trust`) ; refus reconnu à `password authentication failed`.
- Remise en accord : `printf '%s\n%s\n' mdp mdp | compose exec -T base psql … -c '\password notionlike'` (socket locale en `trust`, empreinte SCRAM côté client) ; essayé sur projet jetable et dans la fumée : zéro occurrence dans le journal de la base.
- Arrêt : `docker compose -p <projet> down` lancé depuis un dossier temporaire vide, sans fichier Compose : marche sans fichiers de configuration, garde le volume (essayé).
- Ports de la pile reconnus par `docker ps --filter label=com.docker.compose.project=<projet> --format …{{.Ports}}` ; écoute lue par `lsof -nP -iTCP:<port> -sTCP:LISTEN -Fc`, à défaut `ss`.
- Garde du volume (correctif, ADR-0017) : `verifier_la_configuration` relève `volume_present` avant et après le `run` ; si le volume est apparu, `demarrer` échoue en nommant la version de Compose, sans rien lancer ni supprimer. Le plancher reste Compose 2.24.0 : le relever (2.24.4 ou une version éprouvée) est une décision du dev.
- Écart à la lettre d'AC8 (correctif) : la spec renvoie `URL_BASE_DONNEES` à `infra/.env` et « les autres à `apps/server/.env` » ; `pile.sh` renvoie `NODE_ENV`, `HOTE` et `PORT` à `infra/docker-compose.yml`, parce que l'`environment` du service les impose et l'emporte sur `apps/server/.env` (les y corriger n'aurait aucun effet). Couvert par « F-031-AC8 un refus de %s renvoie à infra/docker-compose.yml » (`infra/tests/pile-demarrer.test.ts`).
- `demarrer` refuse, avant `compose build`, un `infra/.env` ou `apps/server/.env` présent mais qui n'est pas un fichier lisible (dossier, lien cassé, droits) : `preparer` le laisse tel quel, et l'échec de construction qui suivait disait une fausse cause.
- README, phrase sur la CI : le README de `main` disait « Il n'y a pas encore de CI (dette D-001) », devenu faux le même jour par `b8b73b9` (CI GitHub Actions, `.github/workflows/ci.yml`, sur `main` le 2026-10-16). F-031 réécrit ce README ; la phrase est corrigée comme une correction de fait, pas au titre d'un critère : AC29 vise la section « Lancer le serveur et la base », pas « Démarrage ». À accepter ou à sortir du diff par l'orchestrateur ou le dev ; `pile.sh` n'en dépend pas.
- README, ligne « En cas de panne de `pile.sh` » : `docker compose up -d --wait` puis `down` depuis `infra/`, sans `-v` ; c'est le retour arrière de la commande de la pile elle-même.
- Tests sans Docker : arbre temporaire, `/bin/bash`, PATH réduit aux outils du script (`cat dirname grep link mktemp od rm sleep tr`) et à `docker`, `curl`, `lsof` de substitution qui consignent leurs arguments (`infra/tests/aides-pile.ts`) ; ce `docker` crée le volume sur `up` comme sur `run`, sauf quand le dernier `-f` est la surcharge de vérification (ou si l'état porte `run-cree-le-volume`, une Compose qui ignorerait `!reset`). AC18 avec un vrai processus et le vrai `lsof`. Couture d'AC4 : fichiers de `preparer`, environnement bâti comme Compose, `verifier-configuration.ts` réel.

## Pièges / points de vigilance

- Le `docker` de substitution des tests crée le volume sur `run` sauf si le dernier `-f` est `verification-configuration.yml` : un `-f` ajouté après la surcharge dans `pile.sh` la neutraliserait, et les tests le verraient.
- ADR-0017 écrit que « la veille confirme » `!reset` et `--progress quiet` sous Compose 2.24.0 : faux, seule la 5.6.0 a été essayée (veille du 2026-10-16). Relever la version minimale à 2.24.4, ou prouver par une fumée sur une 2.24.x, est une décision du dev ; l'architecte corrige la phrase.
- `run --no-deps` crée le réseau `<projet>_default` même sur un refus : il disparaît au prochain `arreter`.
- `lsof` peut refuser un port que Docker Desktop publierait (écoute sur `*` avec `SO_REUSEADDR`) : refus prudent ; il ne voit pas les processus d'un autre utilisateur.
- `pnpm -w pile …` écrit `$ bash infra/pile.sh …` sur la sortie standard avant le script.
- Tests de la pile : délai de 60 s par test (plusieurs lancements du script) ; sous charge, le délai par défaut de 5 s a été dépassé une fois.
- `infra/pile.sh` ne doit employer que les outils listés dans `OUTILS_DU_SCRIPT` d'`infra/tests/aides-pile.ts` : un outil de plus fait échouer les tests, il faut l'y ajouter.
