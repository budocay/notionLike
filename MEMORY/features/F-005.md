## Décisions prises au code

- Disponibilité d'une commande de bloc (AC11) : une seule composition par type (`etapesDuType` de `edition/types-de-bloc.ts`), jouée sur des **états successifs**, chaque étape partant d'une transaction neuve d'un `EditorState` créé **sans greffons**. Écart avec la note, qui prévoyait `editor.can().chain()` : (a) `can().chain()` ne compose pas (veille) ; (b) une chaîne Tiptap sur une seule transaction fausse les commandes de ProseMirror qui lisent `tr.mapping` (constaté : `liftListItem` rend faux après le retrait de la séquence `/`, donc « Titre » et « Paragraphe » disparaissaient du menu dans une liste) ; (c) `EditorState.apply` passe la transaction aux greffons de l'éditeur, dont l'élévation de version : le jugement à blanc écrivait la version dans Yjs (attrapé par le test de F-005-AC20). L'application rejoue les pas de chaque étape dans **une** transaction de l'éditeur, envoyée seulement si toutes ont abouti (AC16 : une transaction, une mise à jour Yjs).
- Conversions : vers un paragraphe ou un titre, chaque saut de ligne est remplacé par une espace (`insertText` caractère pour caractère), puis `setNodeMarkup`, dans la même transaction (AC1, H16 a) ; vers le bloc code, `setBlockType` sur chaque bloc de texte que son parent admet (marques retirées, AC29), jamais `setNode` (repli `clearNodes`). Le bloc code ne sort jamais d'une liste ; titres et paragraphe en sortent comme depuis F-003.
- Bloc code (`edition/bloc-code.ts`) : `CodeBlock.extend(...).configure({ exitOnTripleEnter: false, enableTabIndentation: false })` ; `renderHTML` qui ne dérive une classe que d'un identifiant de la liste ; `parseHTML` du langage nul ; `Mod-Alt-c` retiré ; Retour arrière d'un bloc code vide en paragraphe **à sa place** (liste comprise) ; Flèche bas : paragraphe ajouté seulement si le bloc est le dernier de la page, sinon le curseur passe au bloc suivant (écart de la veille, cas d'un élément de liste) ; Retour arrière en tête d'un bloc code non vide premier de la page laissé au comportement de ProseMirror (l'extension le convertissait). Greffon de collage d'un éditeur de code remplacé (JSON gardé, objet requis, bloc **sans langage**, refusé là où le schéma refuse un bloc code).
- Garde des langages : `appendTransaction` du bloc code, transactions locales seulement ; tout `codeBlock` dont le début tombe dans une étendue inscrite (cartes des pas) ou dont `language` est posé par un `AttrStep`, avec une valeur hors liste, est réécrit sans langage avant que la liaison n'écrive. Un bloc déplacé (F-006) est donc réinscrit sans langage forgé ; un bloc reçu où l'on tape n'est pas réécrit.
- Liste des commandes : `LISTE_DES_COMMANDES` (nom, repère, mots-clés, type) dans `edition/commandes-de-bloc.ts`, sans import, avec `TypeDeBloc`, `NIVEAUX_DE_TITRE`, `BLOC_CODE` et `memeType` ; exportée avec `commandesFiltrees` par l'interface du module d'édition (données et fonction pures). Le champ `noeud` est retiré : le nœud qu'une commande donne est constaté par le test d'AC21 en l'appliquant. `typeDisponible` mémorise ses jugements par état de l'éditeur (`WeakMap`). Mots-clés : `texte`, `hN`, `puces`, `numéros`, `code`, `pre`.
- Barre : plus affichée dans un bloc vide (F-003-AC41 après F-005, H11) ; **affichée quand la sélection, vide ou non, est entière dans un même bloc code** (sélecteur de langage et « Bloc code » marquée, AC1, AC6, H11 ; une sélection qui déborde du bloc code n'a pas de sélecteur) ; Gras, Italique et Lien indisponibles dans un bloc code (F-028-AC25).
- Menu slash (`edition/menu-slash.ts`) : `@tiptap/suggestion`, priorité 101, préfixe relu dans le document (AC13, `/` après du gras), liste calculée de façon synchrone à chaque changement d'état (les éléments asynchrones de l'utilitaire ne sont pas lus : `items` rend `[]`, et le contrôleur applique lui-même la commande choisie, sans option `command`), placement par `props.mount` avec `strategy: "fixed"`, `flip`, `shift({ padding: 8 })`, coordonnées `PositionDuMenu { gauche, haut }` posées par l'interface dans les variables propres au menu `--menu-x` et `--menu-y`, admises par le contrôle des jetons (`test/aides-styles.ts`, cas fautifs dans `test/styles.test.ts`). L'extension et ses touches sont dans `menu-slash.ts`, la position et la désignation (`useMenuAffiche`) dans `menu-slash-affiche.ts` ; `estAppliqueeDepuisYjs` est dans `liaison.ts`, lu par les marques, le bloc code et le menu ; l'état des liens hors éditeur s'appelle `LiensHorsEditeur`. Menu sans commande : Entrée retenue et sans effet, menu ouvert, séquence gardée (AC11, AC18, H16 b). Fermeture : Échap, effacement, curseur hors de la séquence, clic extérieur (`dismissOnOutsideClick`), démontage, perte du focus de l'éditeur, et mise à jour **reçue** qui change le texte de la séquence ou le balisage du bloc qui la porte (AC19 ; la liaison remplace tout le document à chaque réception, un bloc retiré puis réinséré à l'identique n'est pas distingué). Flèches et Entrée déclarées touches d'interaction du fichier (F-004-AC31) ; aucun modificateur lu : menu ouvert, Mod+Entrée et Alt+Maj+Flèches vont au menu.
- Poignée du curseur dans un bloc vide (`05a4206`, régression de F-006-AC14 relevée par l'audit des ADR) : la barre ne paraissant plus dans un bloc vide, la poignée y posait une sélection de texte vide, « Monter le bloc » était hors d'atteinte et le drapeau `demande` de `useVersLesCommandesDeDeplacement` restait levé (focus volé par la prochaine barre affichée). Le texte d'AC6 (« la barre suit F-003-AC41 seule : affichée sur une sélection non vide, et plus dans un bloc vide ») n'admet pas d'affichage sur une activation explicite avec une sélection vide ; forme retenue, sans exception à AC6 : `selectionnerLeBlocDuCurseur` sélectionne un bloc sans texte **comme nœud** (`NodeSelection`), sélection non vide, et la barre paraît par F-003-AC41. `blocDeLaSelection` lit une sélection de nœud de premier niveau, `deplacerLeBloc` la reporte sur le bloc déplacé ; le lâcher de la poignée de l'éditeur (sélection de plage de nœuds) est inchangé. Le drapeau est remis à zéro au rendu qui suit la demande, barre présente ou non.
- Lecture d'une sélection de profondeur 0 (`7eab6c7`, rejet de l'architecture et du frontend au troisième passage) : la sélection de nœud de la poignée et la sélection de tout le document (Mod+A) commencent à la profondeur 0, où `$from.parent` est le document. `bornesLues` (`edition/types-de-bloc.ts`) rend, pour toute sélection qui n'est pas de texte, les bornes du texte qu'elle couvre (premier bloc de texte, dernier) ; `typeDuBlocCourant`, `lire` de la barre, `etatDesMarques` et `dansUnBlocCode` du schéma la lisent. La composition des types part d'un état dont la sélection est ce texte (`etatDeDepart`) : les commandes de liste ne savent pas lire une sélection de nœud ; le type donné, le curseur est dans le bloc changé (la barre disparaît d'un bloc resté vide, la saisie suit). Sans texte sous une sélection qui n'est pas de texte, Gras et Italique sont indisponibles (rien à marquer) ; Lien l'est par `selectionDansUnBloc`. Un bloc code vide sélectionné par la poignée a son sélecteur de langage. Sous Mod+A, la barre marque le type du premier bloc et Gras, Italique s'appliquent (avant : « Paragraphe » marqué, marques refusées). Les autres lecteurs de la sélection du module sont inscrits, avec leur raison, dans `test/edition/coutures-selection.test.tsx`.
- Collage d'un éditeur de code à la profondeur 0 (`d512d1f`) : `$from.node(-1)` y valait `undefined` (`TypeError` dans `handlePaste`, collage perdu). `blocCodeAdmisALaPlaceDe` juge alors le document : le bloc code sans langage remplace la sélection, comme tout collage. Écarté : le chemin du texte, qui inscrirait des paragraphes, sans le bloc code qu'AC36 demande hors d'un bloc code. Conséquence : un bloc code sélectionné entier (poignée, Mod+A) est remplacé par un bloc code sans langage ; son langage n'est pas repris (le presse-papiers n'en donne jamais, AC7).
- Règle de saisie du bloc code (`c2ac451`, F-005-AC2) : les expressions de l'extension (`backtickInputRegex`, `tildeInputRegex`) n'admettaient que `[a-z]+`, et « `JS␠ », « `c++␠ », « ```py3␠ » restaient du texte. La règle de l'application (`OUVERTURES_DU_BLOC_CODE`) admet tout identifiant sans espace entre les trois accents graves (ou tildes) et l'espace, passé par `langageAdmis` : hors de la liste, un bloc sans langage. Quatre accents graves suivis d'une espace donnent donc aussi un bloc sans langage.
- Menu ouvert, une frappe qui valide une composition (`event.isComposing`) reste à la méthode de saisie (`6c9ef4c`) : `reponseALaTouche` rend la main sans appliquer la commande. Sous jsdom, la vue ne sait pas qu'une composition est en cours : Entrée y coupe alors le bloc, ce qu'un navigateur ne fait pas.
- Police à chasse fixe (H15) : jeton `--font-chasse-fixe` (polices du système, `monospace` en dernier) dans le fichier des jetons, posé sur `pre` et `pre code` (la feuille de base de Tailwind habille `code` à part). Le contrôle des jetons admet `--font-*` en typographie, et `controlerPolices` refuse une police chargée, renvoyée ou sans famille générique (F-004-AC18, AC21).
- Exemption du bloc code dans la couture de la règle des adresses (F-028-AC18) : trois passages exacts de `bloc-code.ts` (attribut de langage, `renderHTML`, `handlePaste`), chacun attendu une fois, et non plus le fichier entier.
- Accessibilité : `aria-controls` et `aria-activedescendant` posés sur l'élément de l'éditeur par un effet React, retirés à la fermeture ; nombre de commandes (« 7 commandes », « Aucune commande ») dans la région d'état de la zone d'édition.

## Dette et limites

- Aucune dette nouvelle numérotée par l'agent.
- Résolus par les décisions du dev du 2026-10-19 (H16) : AC1 (le saut de ligne affiché comme un retour à la ligne puis remplacé à la frappe : remplacé désormais à la conversion, dans les données) ; AC11 et AC18 (Entrée qui coupait l'élément après « /code » : sans effet désormais, partout où le menu ne liste rien) ; H11 (barre dans un bloc code sans sélection, formalisée par AC6).
- Conséquence acceptée (H16 a) : un bloc code converti puis reconverti ne retrouve pas ses sauts de ligne ; Mod+Z les rend.
- Coût de la barre : `commandesDe` juge les sept types à chaque rendu, chaque jugement créant plusieurs `EditorState` sans greffons ; la `WeakMap` par état n'évite que le recalcul sur un même état.
- F-005-AC22 sous Vitest : jsdom et user-event 14.6.7 ne jouent pas l'action par défaut d'un `select` fermé ; l'aide la joue (option voisine, `input`, `change`) seulement si la frappe n'est pas annulée. La saisie au clavier réelle (« py ») n'est prouvée que par le bout en bout (AC34).
- Menu ouvert, Mod+Entrée et Alt+Maj+Flèche haut/bas sont pris par le menu (aucun modificateur lu, F-004-AC31).
- Le bout en bout n'est joué qu'en Chromium sous macOS, hors des hooks (D-003).
- Écran étroit (sans poignée) : un bloc vide ne se déplace qu'au clavier (Alt+Maj+Flèche, F-006-AC18), la barre n'y paraissant pas (AC6) ; F-006-AC28 reste tenu (le pointeur n'est pas la seule voie), mais un usage tactile seul n'a pas de voie. Le lever demande une décision du dev sur la spec (par exemple une commande de sélection du bloc sur écran étroit) ; non numéroté.
- Le correctif de la poignée n'est couvert que sous jsdom ; aucun bout en bout ne joue la poignée du curseur dans un bloc vide, ni Mod+A suivi d'un collage ou d'une commande de la barre.
- Une sélection de texte qui déborde d'une liste (de son texte au paragraphe qui la suit, ou Mod+A) ne sort pas la liste par « Paragraphe » : `liftListItem` refuse une étendue qui déborde de la liste ; comportement antérieur à ce tour, inchangé, non couvert par un critère.
- L'énumération des lecteurs de la sélection lit les sources par expressions régulières (déclarations de premier niveau, lectures `.selection` ou déstructurées) : une lecture qui passerait par un alias (`const s = state; s["selection"]`) lui échapperait ; `typescript` n'est pas une dépendance d'`apps/web`.
