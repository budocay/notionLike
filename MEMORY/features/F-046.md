## Diagnostic (F-046-AC1, AC2)

Deux symptômes, traités séparément (AC2).

### Symptôme 1 : « Unhandled Errors : WebSocket was closed before the connection was established » — cause CONFIRMÉE, dans les aides de test

Enchaînement (lignes de la pile relevée sous charge, sortie identique à celle de la spec) :
1. Un test ouvre un fournisseur : `HocuspocusProviderWebsocket` crée une `PriseAvecCookie` (`apps/server/test/aides-synchro.ts`, classe dans `priseDeFournisseur`), sous-classe de `ws` 8.22.0. La prise est en `CONNECTING`.
2. L'`afterEach` (`synchro-document.test.ts:46`) appelle `fermerLesClients` (`aides-synchro.ts:361-363`), donc `prise.destroy()` puis `disconnect()` (`@hocuspocus/provider` 4.7.0, `hocuspocus-provider.esm.js:373`), qui appelle `WebSocket.close()` sur la prise encore `CONNECTING`.
3. `ws` (`lib/websocket.js:319`) ne lève pas de façon synchrone : il appelle `abortHandshake`, qui émet `error` (« closed before the connection was established ») au tick suivant.
4. Au même moment `destroy()` a retiré les écouteurs `error` du fournisseur : aucun écouteur n'est attaché à la prise, Node lève l'événement `error` en exception non interceptée, que vitest rapporte sous « Unhandled Errors ».
Elle ne survient que si la prise est encore `CONNECTING` à la fermeture, donc dépend du rythme (charge) : une prise déjà ouverte ne la produit pas.

Reproduction avant correction (aides sans l'écouteur permanent) :
- Déterministe : `git stash push apps/server/test/aides-synchro.ts` puis `cd apps/server && npx vitest run test/aides-synchro.test.ts` : 1 test en échec, 2 « Uncaught Exception » (même pile). Avec l'écouteur : 3 tests passent.
- Dans le fichier réel : 12 exécutions de `npx vitest run test/synchro-document.test.ts` en parallèle avec 14 boucles actives (`sh -c 'while :; do :; done'`) sur 10 cœurs, aides sans l'écouteur : 1 exécution sur 12 « Errors 1 error », pile identique (`synchro-document.test.ts:46` -> `fermerLesClients` -> `PriseAvecCookie.close`). 71 tests passent dans chaque exécution.
