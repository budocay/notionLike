### Symptôme 1 : « Unhandled Errors : WebSocket was closed before the connection was established » — cause CONFIRMÉE, dans les aides de test

Enchaînement (lignes de la pile relevée sous charge, sortie identique à celle de la spec) :

1. Un test ouvre un fournisseur : `HocuspocusProviderWebsocket` crée une `PriseAvecCookie` (`apps/server/test/aides-synchro.ts`, classe dans `priseDeFournisseur`), sous-classe de `ws` 8.22.0. La prise est en `CONNECTING`.
2. L'`afterEach` (`synchro-document.test.ts:46`) appelle `fermerLesClients` (`aides-synchro.ts:374`), donc `prise.destroy()` puis `disconnect()` (`@hocuspocus/provider` 4.7.0, `hocuspocus-provider.esm.js:373`), qui appelle `WebSocket.close()` sur la prise encore `CONNECTING`.
3. `ws` (`lib/websocket.js:319`) ne lève pas de façon synchrone : il appelle `abortHandshake`, qui émet `error` (« closed before the connection was established ») au tick suivant.
4. Au même moment `destroy()` a retiré les écouteurs `error` du fournisseur : aucun écouteur n'est attaché à la prise, Node lève l'événement `error` en exception non interceptée, que vitest rapporte sous « Unhandled Errors ».
   Elle ne survient que si la prise est encore `CONNECTING` à la fermeture, donc dépend du rythme (charge) : une prise déjà ouverte ne la produit pas.

Reproduction avant correction (aides sans le correctif de `close`) :

- Déterministe : `git stash push apps/server/test/aides-synchro.ts` puis `cd apps/server && npx vitest run test/aides-synchro.test.ts` : 1 test en échec, 2 « Uncaught Exception » (même pile). Avec le correctif resserré : 4 tests passent.
- Dans le fichier réel : 12 exécutions de `npx vitest run test/synchro-document.test.ts` en parallèle avec 14 boucles actives (`sh -c 'while :; do :; done'`) sur 10 cœurs, aides sans l'écouteur : 1 exécution sur 12 « Errors 1 error », pile identique (`synchro-document.test.ts:46` -> `fermerLesClients` -> `PriseAvecCookie.close`). 71 tests passent dans chaque exécution.

## Correctif (resserré après revue)

`PriseAvecCookie` (`aides-synchro.ts:312`) surcharge `close()` : si `readyState === WebSocket.CONNECTING`, elle pose `this.once("error", () => undefined)` juste avant `super.close()`. L'absorption ne vaut que pour la fermeture d'une prise encore en connexion, une seule erreur, et disparaît ensuite. Refus de connexion, erreur de protocole, erreur en cours de session restent visibles. `priseDeFournisseur` prend `Pick<ServeurDEssai, "urlDeSynchro" | "urlPublique">` (plus de conversion dans le test).

Tests (`aides-synchro.test.ts`) : fermeture en `CONNECTING` (readyState `WebSocket.CLOSED`, zéro écouteur d'erreur résiduel, connexions vides) ; une autre erreur de prise reste visible (`emit("error")` sans écouteur lève) ; prise déjà close (fermée explicitement, attente de `CLOSED`, puis `fermerLesClients` deux fois : readyState inchangé, aucun incident de processus, connexions vides) ; couture AC7 lisant chaque fichier une fois : `synchro-limites` et `synchro-plafonds` sont les seuls observateurs d'incidents parmi les appelants, aucun n'ouvre de `priseDeFournisseur`/fournisseur Hocuspocus (limites utilise des clients bruts, plafonds une requête HTTP) et `fermerLesClients` est hors de la fenêtre d'observation de limites.

Échec sans correctif (2026-10-30) : en retirant la ligne `this.once("error", …)` de `close`, `npx vitest run test/aides-synchro.test.ts` donne `Tests 1 failed | 3 passed`, `Errors 1 error` (Uncaught Exception), c'est le test « ferme une prise encore en cours de connexion ». Avec le correctif : 4 passés.
