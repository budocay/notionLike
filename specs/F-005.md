# SPEC F-005 — Bloc code et commandes slash

Statut : brouillon
Tier : structurel
Revue : reviewer-frontend

- Objectif (une phrase, côté métier) : une personne insère dans une page un bloc de code, dont le texte est gardé tel quel, et choisit le type d'un bloc sans quitter le clavier, en tapant `/` puis quelques lettres, sans compte ni réseau.
- Vocabulaire :
  - « bloc code » : un bloc dont le contenu est du texte brut, sauts de ligne compris, sans marque ni bloc imbriqué, et qui porte un langage facultatif.
  - « langage » : l'attribut du bloc code qui nomme le langage de son texte. « liste des langages » : la liste fermée des identifiants que l'application propose (H5) ; « Texte brut » désigne l'absence de langage.
  - « commande de bloc » : une commande qui donne un type au bloc courant. Sept dans cette feature : « Paragraphe », « Titre 1 », « Titre 2 », « Titre 3 », « Liste à puces », « Liste numérotée », « Bloc code ». « liste des commandes » : leur déclaration unique (libellé, mots-clés, type de bloc), dont la barre de blocs et le menu slash tirent tous deux leur contenu.
  - « menu slash » : la liste de commandes de bloc ouverte par la frappe de `/` dans l'éditeur. « séquence » : le `/` et le texte saisi à sa suite tant que le menu est ouvert. « commande active » : celle que la touche Entrée appliquerait.
  - « commande indisponible » : une commande que le schéma ne permet pas d'appliquer au bloc courant ; elle est affichée, annoncée comme indisponible, et sans effet.
  - « Mod » : la touche Ctrl sous Windows et Linux, la touche Cmd sous macOS.
  - « version du document de page » : l'entier défini par F-003 (AC23, H4) ; un document sans version écrite est de version 1. « version lue », « élever la version », « forme stockée de la version » : définis par `specs/F-003.md`, qui livre la lecture et l'opération d'élévation (F-003-AC23, AC31).
  - « table des versions » : la liste, tenue en un seul endroit, qui donne pour chaque version du document de page les nœuds, les attributs et les marques du schéma ; chaque ligne contient la précédente. « version d'un élément » : la ligne qui introduit ce nœud, cet attribut ou cette marque. « version prise en charge » : le numéro de la dernière ligne.
  - « éditeur », « bloc », « schéma », « contenu lu », « barre de blocs », « document de page » : définis par `specs/F-003.md`. Le contenu lu comprend désormais le texte et le langage de chaque bloc code.
- Critères d'acceptation :
  - Bloc code
    - F-005-AC1 : QUAND l'utilisateur active « Bloc code » sur un paragraphe ou un titre, LE SYSTÈME DOIT en faire un bloc code sans langage qui conserve son texte ; QUAND il active « Paragraphe » ou un titre sur un bloc code, LE SYSTÈME DOIT lui donner ce type en conservant tous les caractères de son texte, sauts de ligne compris (le schéma n'a pas de saut de ligne hors du bloc code : ils restent dans le texte et s'affichent comme des espaces) ; la barre de blocs DOIT marquer « Bloc code » quand le curseur est dans un bloc code.
    - F-005-AC2 : QUAND l'utilisateur saisit en tête d'un paragraphe vide trois accents graves suivis d'une espace, LE SYSTÈME DOIT transformer ce paragraphe en bloc code sans langage, sans conserver la séquence ; QUAND un identifiant de la liste des langages est saisi entre les accents graves et l'espace, LE SYSTÈME DOIT donner ce langage au bloc ; SI l'identifiant saisi n'est pas dans la liste, ALORS LE SYSTÈME DOIT créer le bloc code sans langage.
    - F-005-AC3 : QUAND l'utilisateur presse Entrée dans un bloc code, LE SYSTÈME DOIT insérer un saut de ligne dans ce bloc, sans créer de bloc.
    - F-005-AC4 : QUAND l'utilisateur presse Mod+Entrée dans un bloc code, ou Flèche bas à la fin d'un bloc code qui est le dernier bloc de la page, LE SYSTÈME DOIT créer un paragraphe à la suite et y placer le curseur ; QUAND il presse Retour arrière en tête d'un bloc code vide, LE SYSTÈME DOIT en faire un paragraphe vide.
    - F-005-AC5 : TANT QUE le curseur est dans un bloc code, LE SYSTÈME DOIT inscrire tel quel tout ce qui est saisi : aucune règle de saisie de F-003-AC9 ni d'une autre feature NE DOIT s'y déclencher, la frappe de `/` NE DOIT PAS ouvrir le menu slash, et la touche Tab NE DOIT rien modifier dans le document.
    - F-005-AC6 : QUAND le curseur est dans un bloc code, LE SYSTÈME DOIT afficher dans la barre de blocs un sélecteur « Langage du bloc code » qui propose « Texte brut » et la liste des langages et montre celui du bloc ; QUAND l'utilisateur en choisit un, LE SYSTÈME DOIT l'enregistrer dans le bloc (« Texte brut » : aucun langage) sans modifier son texte ; hors d'un bloc code, le sélecteur NE DOIT PAS être proposé.
    - F-005-AC7 : QUAND l'utilisateur colle un contenu dans un bloc code, LE SYSTÈME DOIT n'en inscrire que le texte, sauts de ligne conservés, dans ce seul bloc ; QUAND il colle hors d'un bloc code un contenu riche qui contient un élément `pre`, LE SYSTÈME DOIT en faire un bloc code sans langage qui en porte le texte ; le langage NE DOIT jamais être tiré du presse-papiers.
    - F-005-AC8 : LE SYSTÈME DOIT rendre un bloc code par un élément `pre` qui contient un élément `code`, dans une police à chasse fixe, espaces et sauts de ligne conservés, sans coloration du texte.
  - Erreurs et limites du bloc code
    - F-005-AC9 (langage hors liste, à la lecture) : SI un bloc code du document porte, à l'ouverture ou après une mise à jour Yjs appliquée pendant l'affichage, un langage absent de la liste des langages ou qui n'est pas une chaîne, ALORS LE SYSTÈME DOIT afficher son texte, montrer « Texte brut » dans le sélecteur, n'émettre aucune mise à jour Yjs de ce fait, et ne dériver de cette valeur aucune classe, aucun attribut ni aucun texte du DOM ; un test DOIT écrire par `yjs` seul les valeurs `x fixed inset-0`, `"><script>alert(1)</script>`, une chaîne de 10 000 caractères et un nombre, puis constater qu'aucune n'apparaît dans un attribut d'un élément de l'éditeur.
    - F-005-AC10 : SI le texte d'un bloc code contient du balisage HTML ou un script, ALORS LE SYSTÈME DOIT l'afficher comme du texte sans l'interpréter ; le test de F-003-AC20 DOIT couvrir les fichiers de cette feature.
    - F-005-AC11 (commande indisponible) : SI le schéma ne permet pas de donner au bloc courant le type d'une commande de bloc (par exemple, à confirmer par la veille, « Bloc code » dans le premier paragraphe d'un élément de liste : H7), ALORS LE SYSTÈME DOIT exposer cette commande comme indisponible dans la barre de blocs et dans le menu slash, et son activation NE DOIT émettre aucune mise à jour Yjs.
  - Menu slash
    - F-005-AC12 : QUAND l'utilisateur saisit `/` en tête d'un paragraphe, d'un titre ou du paragraphe d'un élément de liste, ou juste après une espace, LE SYSTÈME DOIT inscrire le `/` dans le texte et ouvrir le menu slash, qui liste les sept commandes de bloc dans l'ordre du vocabulaire, la première étant la commande active.
    - F-005-AC13 : SI le `/` est saisi juste après un caractère qui n'est pas une espace, ou dans un bloc code, ALORS LE SYSTÈME NE DOIT PAS ouvrir le menu slash.
    - F-005-AC14 : TANT QUE le menu slash est ouvert, QUAND l'utilisateur saisit ou efface du texte à la suite du `/`, LE SYSTÈME DOIT ne lister que les commandes dont le libellé ou un mot-clé contient ce texte, sans tenir compte de la casse ni des accents, dans l'ordre d'origine, la première restant la commande active.
    - F-005-AC15 : TANT QUE le menu slash est ouvert, QUAND l'utilisateur presse Flèche bas ou Flèche haut, LE SYSTÈME DOIT rendre active la commande disponible suivante ou précédente, en bouclant de la dernière à la première et inversement ; ces touches, et Entrée, NE DOIVENT alors ni déplacer le curseur ni modifier le document par elles-mêmes.
    - F-005-AC16 : QUAND l'utilisateur presse Entrée, ou clique sur une commande, menu slash ouvert, LE SYSTÈME DOIT retirer la séquence du texte, donner au bloc courant le type de la commande en conservant le reste de son texte, fermer le menu et laisser le curseur dans ce bloc, le tout en une seule mise à jour Yjs.
    - F-005-AC17 : QUAND l'utilisateur presse Échap, efface le `/`, déplace le curseur hors de la séquence, clique hors du menu ou change de page, LE SYSTÈME DOIT fermer le menu slash en laissant le texte tel qu'il est ; après Échap, le menu NE DOIT PAS se rouvrir pour ce même `/`.
    - F-005-AC18 : SI aucune commande ne correspond au texte saisi, ALORS LE SYSTÈME DOIT afficher « Aucune commande » dans le menu ; la touche Entrée DOIT alors fermer le menu et agir comme F-003-AC7 et AC10 le prescrivent, la séquence restant dans le texte.
    - F-005-AC19 : SI une mise à jour Yjs appliquée pendant que le menu slash est ouvert modifie ou retire la séquence, ALORS LE SYSTÈME DOIT fermer le menu, sans exception levée et sans perdre le texte que l'utilisateur a saisi ailleurs.
    - F-005-AC20 : LE SYSTÈME NE DOIT émettre, du fait de l'ouverture, du filtrage, de la navigation ou de la fermeture du menu slash, aucune mise à jour Yjs autre que celles du texte saisi : l'état du menu ne vit pas dans le document de page.
    - F-005-AC21 (une seule liste de commandes) : LE SYSTÈME DOIT tirer la barre de blocs et le menu slash de la même liste des commandes ; un test DOIT énumérer les types de bloc de la dernière ligne de la table des versions et échouer si l'un d'eux n'a pas de commande dans la barre et dans le menu, ou si une commande donne un type absent du schéma.
  - Accessibilité
    - F-005-AC22 : LE SYSTÈME DOIT exposer le menu slash comme une liste d'options nommée « Commandes de bloc », chaque commande comme une option qui porte un identifiant, un nom accessible en français et son état (active, indisponible) ; TANT QUE le menu est ouvert, l'éditeur DOIT garder le focus et désigner le menu et la commande active par `aria-controls` et `aria-activedescendant`, retirés à la fermeture ; le nombre de commandes listées, ou « Aucune commande », DOIT être annoncé aux technologies d'assistance à chaque changement du filtre ; le sélecteur de langage DOIT être atteignable et utilisable au clavier seul, avec son nom accessible ; l'éditeur DOIT rester la zone de texte multiligne « Contenu de la page » de F-003-AC16.
  - Version du format et montée de version
    - F-005-AC23 (numéro de version) : LE SYSTÈME DOIT ajouter à la table des versions une ligne dont le numéro est la version prise en charge par `main` au premier commit de code de cette feature, plus un (3 dans l'ordre recommandé, où F-028 est livrée avant ; 2 si F-005 est la première feature livrée qui étend le schéma ; voir H1), et qui ajoute à la ligne précédente le nœud `codeBlock` et son attribut `language` ; un test DOIT vérifier que les numéros de la table se suivent depuis 1 sans trou, que chaque ligne contient la précédente, que le schéma de l'éditeur est exactement la dernière ligne et que la version prise en charge par `@notionlike/document` est son numéro.
    - F-005-AC24 (lecture d'une version antérieure) : QUAND un document de page d'une version antérieure prise en charge est ouvert, LE SYSTÈME DOIT afficher tout son contenu, n'émettre aucune mise à jour Yjs à l'ouverture et laisser sa version inchangée ; TANT QUE l'utilisateur n'y inscrit aucun élément d'une version supérieure à celle du document, LE SYSTÈME NE DOIT PAS écrire de version ; un test DOIT le prouver pour chaque ligne antérieure de la table, sur un document rempli selon cette ligne puis modifié par une frappe dans un paragraphe et par une commande de bloc autre que « Bloc code ».
    - F-005-AC25 (écriture de la version) : QUAND une modification locale inscrit pour la première fois dans un document un élément dont la version dépasse celle du document, LE SYSTÈME DOIT élever la version du document à celle de cet élément avant, ou dans, la transaction Yjs qui inscrit cet élément, quel que soit le chemin (barre de blocs, menu slash, règle de saisie, collage, dépôt) ; un test DOIT, pour chaque chemin, écouter l'événement `update` du document et constater qu'aucune mise à jour portant un bloc code n'est émise avant celle qui porte la version.
    - F-005-AC26 (la version ne baisse jamais) : QUAND deux répliques élèvent en même temps la version d'un même document à deux valeurs différentes puis convergent, quel que soit l'ordre d'application des mises à jour, LE SYSTÈME DOIT lire sur les deux la plus haute des deux valeurs : la version lue est la plus haute jamais inscrite (F-003-AC23), ce que F-003-AC31 garantit et prouve pour la forme stockée et que cette feature ne réécrit pas, de sorte qu'une application qui ne prend en charge qu'une version inférieure refuse le document (F-003-AC19) ; une annulation (Mod+Z) NE DOIT PAS abaisser la version. Ce volet annulation est entièrement à la charge de cette feature, F-003 ne pouvant pas le prouver (F-003-AC32, F-003 H4) : un test DOIT insérer un bloc code par l'éditeur dans un document de version antérieure, annuler jusqu'à épuiser l'historique, puis constater que la version lue est toujours celle du bloc code, sur ce document et sur un document vierge qui en reçoit les mises à jour.
    - F-005-AC27 (refus d'une version supérieure) : SI la version d'un document de page dépasse la version prise en charge, ALORS LE SYSTÈME DOIT se comporter comme F-003-AC19 et F-003-AC29 le prescrivent ; un test DOIT ouvrir un document de la version prise en charge plus un, qui contient un nœud et une marque absents du schéma, et constater qu'aucun éditeur n'est créé, qu'aucun événement `update` n'est émis et que l'état encodé du document est le même, octet pour octet, qu'avant l'ouverture.
    - F-005-AC28 (couture du format) : LE SYSTÈME DOIT enregistrer un bloc code dans le fragment XML du document de page comme un nœud `codeBlock` qui ne contient que du texte, sans marque, avec le seul attribut `language` (omis ou nul quand il n'y a pas de langage), sans nouveau type racine ; un test DOIT énumérer les appelants du format du document de page (le module d'édition, le module de persistance, la façade de `@notionlike/document` et tout autre module d'`apps/web` ou du serveur qui lit le fragment ou la version) et échouer si l'un d'eux n'est couvert par aucun test qui ouvre un document de chaque ligne de la table ; un document qui contient un bloc code de plusieurs lignes avec langage, enregistré par le module de persistance puis relu dans un document Yjs vierge, DOIT donner le même contenu lu.
    - F-005-AC29 : SI le schéma contient des marques (F-028 livrée), ALORS LE SYSTÈME DOIT les retirer du texte d'un bloc transformé en bloc code, en conservant ce texte, et n'en accepter aucune dans un bloc code, par aucun chemin (commande, raccourci, règle de saisie, collage).
  - Convergence
    - F-005-AC30 : QUAND deux répliques d'un même document de page ont été modifiées séparément (l'une saisit du texte dans un bloc code pendant que l'autre en change le langage ; les deux saisissent du texte en deux endroits du même bloc code) puis convergent, quel que soit l'ordre d'application des mises à jour, LE SYSTÈME DOIT lire sur les deux le même contenu, où figurent les textes saisis et le langage choisi.
    - F-005-AC31 (changement de type concurrent d'une saisie, limite) : QUAND une réplique change le type d'un bloc (commande de bloc ou menu slash) pendant que l'autre saisit du texte dans ce même bloc, puis qu'elles convergent, LE SYSTÈME DOIT lire sur les deux le même contenu ; la présence du texte saisi par l'autre réplique n'est pas garantie (H8) ; un test DOIT constater le contenu obtenu et l'inscrire tel quel dans son attendu.
  - Structure et coutures
    - F-005-AC32 (couture de la version prise en charge de `@notionlike/document`) : LE SYSTÈME DOIT relever la version prise en charge par `@notionlike/document` au numéro de la ligne de F-005-AC23, ajouter cette ligne à la table des versions sans retoucher les lignes précédentes, et élever la version d'un document par la seule opération de F-003-AC31, sans la modifier ni la doubler, sans changer la forme stockée de la version ni sa lecture (F-003-AC23), sans nouveau type racine et sans nouvel export ; les exports déjà livrés DOIVENT rester inchangés (mêmes noms, mêmes signatures, mêmes codes d'erreur pour les mêmes refus) et les tests de couture des exports (F-003-AC24 et ceux des features livrées) DOIVENT passer sans que leurs listes attendues changent ; un test DOIT énumérer les appelants de la lecture de la version, de la vérification de version et de l'opération d'élévation (le module d'édition, et tout autre module d'`apps/web` ou du serveur qui s'en sert) et échouer si l'un d'eux n'est couvert par aucun test qui lui présente un document de chaque ligne de la table et un document de la version prise en charge plus un ; le paquet DOIT rester exécutable sous Node sans DOM avec `yjs` pour seule dépendance d'exécution.
    - F-005-AC33 : LE SYSTÈME DOIT garder vrais F-003-AC21 (aucune requête réseau du fait de l'éditeur, menu slash compris), F-003-AC26 (une seule instance de `yjs`, manifestes et fichier de verrou relus après l'ajout des dépendances de cette feature), F-003-AC27 (Tiptap, ProseMirror, leur liaison et l'utilitaire de suggestion importés par le seul module d'édition, dont l'interface n'expose aucun de leurs types ; `pnpm contrats` sans violation) et F-003-AC30 (`prosemirror-view` à 1.42.3 au moins).
  - Bout en bout
    - F-005-AC34 : QUAND la commande de test de bout en bout est lancée, LE SYSTÈME DOIT dérouler dans un navigateur réel, par des frappes réelles, le scénario : dans une page vide, taper `/`, constater le menu affiché près du curseur et entièrement dans la fenêtre, taper `cod`, valider par Entrée, saisir deux lignes de code dont une contient `<b>` et `# `, choisir un langage, sortir par Mod+Entrée, taper `/tit`, descendre d'une commande par Flèche bas, valider, saisir un titre, recharger, constater le même contenu, le bloc code rendu par `pre` et le langage choisi.
- Hors périmètre (explicitement) :
  - Coloration syntaxique, numéros de ligne, repli de code, bouton « copier », exécution de code : voir H4.
  - Indentation par la touche Tab dans un bloc code (H6) ; détection automatique du langage ; langages hors de la liste.
  - Code en ligne (marque) : aucune feature ne le porte à ce jour. Gras, italique, liens : F-028.
  - Commandes du menu slash autres que les sept commandes de bloc : insertion d'image (F-022), de table (F-018), mise en forme, mention, date, modèle de page. Chaque feature qui ajoute un type de bloc ajoute sa commande à la liste (F-005-AC21).
  - Menu slash hors de l'éditeur (titre de page, barre latérale) ; palette de commandes et raccourcis globaux : F-024.
  - Insertion d'un bloc à un autre endroit que le bloc courant ; glisser-déposer : F-006.
  - Synchronisation, rencontre en direct de deux versions de l'application sur un même document : F-013 (voir H2).
  - Conversion des documents existants : aucun document n'est réécrit à l'ouverture (F-005-AC24).
  - Retour à une version antérieure de l'application sur un appareil : un document élevé y est refusé, sans chemin de retour.
  - Saisie tactile ; navigateurs autres que Chromium dans le test de bout en bout.
- Hypothèses tranchées par agent-planif en l'absence du dev, que la validation de cette spec entérine :
  - H1 — Règle d'incrément de la version, commune à F-005, F-022 et F-028, indépendante de l'ordre de livraison : la version qu'une feature introduit est la version prise en charge par `main` au moment de son premier commit de code, plus un ; `agent-architecte-conception` l'inscrit dans sa conception et dans la table des versions. Les versions sont cumulatives : la ligne N contient la ligne N-1, et une application qui prend en charge N ouvre toutes les versions de 1 à N. Ordre recommandé, non imposé : F-028 (version 2), puis F-005 (version 3), puis F-022 (version 4). Tranché ainsi plutôt que par un ordre fixe parce que la ROADMAP laisse ces trois features libres entre elles et qu'un numéro réservé d'avance serait faux dès qu'une livraison s'inverse. Garde-fou : deux branches qui prendraient le même numéro modifient la même ligne de la table, tenue en un seul endroit, et une branche ne fusionne qu'une à la fois (`AGENTS.md`) ; la seconde prend le numéro suivant, et F-005-AC23 échoue tant que ce n'est pas fait. Un numéro de version livré ne change plus jamais de sens : difficile à défaire.
  - H2 — Montée de version paresseuse, écrite par le client qui inscrit le premier élément nouveau, jamais à l'ouverture. Lire un document de version antérieure ne l'écrit pas (F-005-AC24, qui prolonge F-003-AC2 et H7). La version n'est élevée que par la modification qui inscrit le premier bloc code (F-005-AC25), à la version de cet élément et non à la plus haute que le client connaît : un document sans bloc code reste lisible par une application plus ancienne. Conséquence acceptée : dès qu'un bloc code est inséré, une application plus ancienne refuse la page entière (F-003-AC19), sans mode lecture seule. Deux clients de versions différentes sur la même page : dans cette feature, ils ne se voient pas en direct (deux onglets ne se voient qu'après rechargement, F-002 H7) ; l'onglet ancien resté ouvert ne reçoit pas le contenu nouveau et ne peut donc pas le détruire, et à son rechargement il lit la version élevée avant de créer l'éditeur et refuse (F-003-AC19). Avec la synchronisation, le client ancien reçoit la version dans une mise à jour : si elle précède le contenu, F-003-AC29 détruit sa liaison à temps ; si elle arrive dans la même mise à jour que le contenu, rien n'est garanti (F-003 H4, cas (a), non vérifié par la veille) : F-013 doit vérifier la version avant d'appliquer une mise à jour reçue. Cette spec ne réduit pas ce risque et ne le déclare pas couvert.
  - H3 — La version ne doit jamais baisser, y compris quand deux clients l'élèvent en même temps à deux valeurs différentes. C'est F-003 qui le garantit et le livre, pas cette feature : la version lue est la plus haute jamais inscrite (F-003-AC23), l'opération d'élévation et sa convergence sont dans `@notionlike/document` (F-003-AC31), et la forme stockée de la version, hors du fragment du contenu, est consignée par un ADR de la conception de F-003 (F-003 H4). Il n'y a pas de valeur unique dont la dernière écriture gagnerait, ni rien à écrire à côté d'elle : avec une telle valeur, un client de version 2 et un client de version 3 qui élèvent ensemble un document pourraient le laisser à 2 alors qu'il contient un élément de la version 3, que le client de version 2 supprimerait ensuite pour tous. Une application limitée à la version 1 a la même lecture, puisqu'elle vient de F-003 : elle lit la version élevée et refuse le document (F-003-AC19). Cette feature ne change donc ni la forme stockée, ni la lecture, et n'ajoute ni type racine ni export : elle relève la version prise en charge, ajoute sa ligne à la table des versions et appelle l'opération de F-003 (F-005-AC23, AC25, AC32). Ce qui reste entièrement à sa charge : prouver qu'une annulation n'abaisse pas la version (F-005-AC26), ce que F-003 ne peut pas faire, toute élévation y détruisant l'éditeur avec son historique (F-003-AC32). La forme stockée est hors du fragment, seul contenu que l'éditeur écrit, mais la portée exacte de l'historique de la liaison n'a pas été vérifiée par la veille : à confirmer par la veille. Si l'historique atteignait la forme stockée, F-005-AC26 échouerait : à remonter au dev avant toute retouche de la forme stockée, qui appartient à F-003 et se défait mal.
  - H4 — La coloration syntaxique est exclue de cette feature. Elle demande une dépendance directe de plus (la veille relève un paquet `@tiptap/extension-code-block-lowlight`, sous licence MIT, sans en avoir étudié ni les dépendances ni le poids), un jeu de couleurs à soumettre aux contrôles de F-004 (contraste, jetons), et n'est demandée ni par la fiche ni par la ROADMAP. Le langage est pourtant enregistré dès maintenant (F-005-AC6), pour que la coloration, le jour où elle vient, ne soit ni un changement de format ni un incrément de version : elle ne ferait que lire un attribut déjà présent. Elle n'a pas de ligne dans la ROADMAP : le dev décide si elle en reçoit une.
  - H5 — Liste des langages, fermée : `bash`, `css`, `html`, `javascript`, `json`, `markdown`, `python`, `sql`, `typescript`, `yaml`. Le format accepte n'importe quelle chaîne dans `language` ; la liste est une règle de l'application, pas du format : l'allonger n'incrémente pas la version, parce qu'une application qui ne connaît pas un langage affiche le bloc comme du texte brut sans rien écrire (F-005-AC9). Une valeur hors liste n'est jamais recopiée dans le DOM : un autre client peut écrire n'importe quoi dans le fragment, et une valeur comme `x fixed inset-0`, recopiée dans une classe, habillerait le bloc avec les classes utilitaires de l'application. Les identifiants devront coïncider avec ceux de la bibliothèque de coloration le jour où elle est choisie : à confirmer par la veille à ce moment-là ; d'ici là ils n'engagent que le sélecteur.
  - H6 — La touche Tab n'est pas capturée dans un bloc code : elle reste la touche de navigation au clavier, pour qu'on puisse toujours quitter l'éditeur sans souris (F-003-AC11 ne la capture que dans une liste). L'indentation se fait à l'espace. Choix d'accessibilité contre confort de saisie ; il se défait sans coût (aucun format touché). Les sorties de F-005-AC4 existent pour qu'un bloc code en fin de page ne soit jamais une impasse ; ce que l'extension de Tiptap apporte d'elle-même (sortie par Entrée répétée, par Flèche bas) est à confirmer par la veille, et le module d'édition écrit ce qui manque.
  - H7 — Le bloc code s'appuie sur l'extension unitaire de Tiptap, au numéro commun des paquets `@tiptap/*` (`3.31.4`). La veille constate que le kit de départ contient un nœud nommé `codeBlock`, mais ne couvre pas son paquet unitaire. À confirmer par la veille, sans rien avancer ici : le nom exact du paquet, sa licence, ses dépendances, le nom et la valeur par défaut de l'attribut de langage, la classe qu'il dérive du langage au rendu (F-005-AC9 l'interdit pour une valeur hors liste), sa règle de saisie (F-005-AC2), l'interdiction des marques dans son contenu (F-005-AC29), et les endroits où le schéma l'accepte. Sur ce dernier point, F-003 ne dit que ceci (vocabulaire, « bloc ») : seules ses commandes limitent le contenu d'un élément de liste aux paragraphes et aux listes imbriquées ; la règle de contenu d'un élément de liste est celle de l'extension de Tiptap, que F-003 ne resserre pas, et la veille n'a pas vérifié ce qu'elle admet après le premier paragraphe. Qu'un bloc code puisse se trouver dans un élément de liste (par une commande, un collage ou un document reçu), et que « Bloc code » soit impossible dans son premier paragraphe (l'exemple de F-005-AC11), sont donc à confirmer par la veille. Tranché, quel que soit son constat : un bloc code est accepté partout où le schéma de F-003 accepte un bloc, sans modifier la règle de contenu des éléments de liste ; là où la transformation est impossible, la commande est indisponible (F-005-AC11).
  - H8 — Changer le type d'un bloc pendant qu'un autre client y écrit. Dans le fragment Yjs, le nom d'un élément ne se change pas : donner un autre type à un bloc revient vraisemblablement à supprimer l'élément et à en insérer un autre, comme pour un déplacement, dont la veille a constaté qu'il perd la modification concurrente (F-003 H1). Ce cas précis n'a pas été exécuté par la veille : à confirmer. F-003-AC15 ne couvre que deux blocs différents. F-005 multiplie les changements de type (menu slash) sans rien y changer : elle exige seulement la convergence et fait constater le résultat par un test (F-005-AC31), pour qu'il soit connu avant F-013. Aucune parade n'est promise.
  - H9 — Le menu slash s'appuie sur l'utilitaire de suggestion de Tiptap (`@tiptap/suggestion`, relevé par la veille au numéro `3.31.4` sous licence MIT), comme F-003 (H1) l'annonçait : il porte ce qu'un menu maison devrait réécrire dans l'éditeur (repérer le caractère déclencheur et l'étendue de la séquence, intercepter les touches avant l'éditeur, suivre la séquence quand le texte change). La liste affichée, elle, est un composant de l'application : aucune bibliothèque de menu ni de positionnement n'est ajoutée ; le menu est placé d'après la position du curseur que le module d'édition fournit, sous le curseur, ou au-dessus s'il sortirait de la fenêtre.
  - H10 — Le `/` est inscrit dans le texte à la frappe et retiré à l'application d'une commande (F-005-AC12, AC16). Il traverse donc la persistance, et la synchronisation plus tard : un autre appareil peut voir passer `/tit`. Accepté : c'est le fonctionnement de l'utilitaire de suggestion, et le texte de l'utilisateur n'est jamais retenu hors du document. Le menu ne s'ouvre pas au milieu d'un mot (F-005-AC13), pour qu'une adresse ou une fraction ne le déclenche pas. Retirer la séquence et changer le type en une seule mise à jour (F-005-AC16) évite qu'un autre appareil voie le bloc dans un état intermédiaire et donne une seule étape d'annulation : faisable en principe par une seule transaction de l'éditeur, à confirmer par la veille.
  - H11 — La barre de blocs de F-003 reste (F-003 H8) et reçoit « Bloc code » et le sélecteur de langage. Le sélecteur vit dans la barre et non dans le bloc lui-même : un contrôle affiché dans le bloc demanderait une vue de nœud sur mesure dans l'éditeur, plus coûteuse à rendre accessible et à tester.
