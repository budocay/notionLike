# SPEC F-044 — Modèles : modèles de page et modèles de ligne de table

Statut : validée
Tier : structurel
Revue : reviewer-frontend

- Objectif (une phrase, côté métier) : une équipe garde des modèles (une page déjà structurée, une ligne de table pré-remplie) et en crée de nouvelles en un geste, comme les « Templates » de Notion, sans réseau et avec les mêmes droits que le reste de l'espace.
- Origine : retour du dev sur la RC1 (2026-10-30, donnée) : « on ne peut pas créer de template, de labels etc etc je t'avais pourtant dit de t'inspirer de Notion ». Aucune spec ne couvrait les modèles. Les étiquettes sont dans `specs/F-045.md`.
- Vocabulaire :
  - « modèle de page » : une page de type `page` marquée comme modèle : elle a un titre et un contenu comme toute page, ne figure pas dans l'arborescence des pages, et est listée dans la section « Modèles » de la barre latérale.
  - « page créée depuis un modèle » : une nouvelle page ordinaire dont le titre et le contenu (tous les blocs) sont une copie de ceux du modèle au moment de la création ; ensuite, plus aucun lien entre les deux.
  - « modèle de ligne » : un nom et, pour chaque colonne de la table, une valeur par défaut (vide ou conforme au type de la colonne). Il vit dans le document de la table qu'il sert ; il ne porte ni contenu de page (une ligne n'est pas une page, F-017) ni date relative.
  - « ligne créée depuis un modèle » : une ligne ordinaire dont les cellules ont, à la création, les valeurs par défaut du modèle ; ensuite, plus aucun lien.
  - « document d'espace », « document de page », « document de table », « table lue », « façade », « réplique », « converger », « erreur typée » : définis par `specs/F-001.md`, `specs/F-003.md`, `specs/F-017.md`. « écran de table », « grille », « boîte », « barre latérale », « corbeille » : `specs/F-018.md`, `specs/F-002.md`, `specs/F-007.md`. « colonne `etiquettes` » : `specs/F-045.md`.
- Critères d'acceptation :
  - Modèles de page
    - F-044-AC1 : QUAND l'utilisateur active « Nouveau modèle de page » dans la section « Modèles » de la barre latérale, LE SYSTÈME DOIT créer un modèle au titre vide et au contenu vide, l'afficher dans la section avec le libellé « Sans titre », le sélectionner, ouvrir la saisie de son titre (comme F-002-AC5) et l'ouvrir dans l'éditeur ordinaire de F-003, sans le placer dans l'arborescence des pages.
    - F-044-AC2 : QUAND l'utilisateur active « Enregistrer comme modèle » sur une page de type `page` (menu de la rangée ou de l'en-tête), LE SYSTÈME DOIT créer un modèle de page dont le titre et le contenu sont une copie de ceux de la page à cet instant, laisser la page d'origine intacte et annoncer « Modèle enregistré ». La commande NE DOIT PAS être offerte sur une table.
    - F-044-AC3 : QUAND l'utilisateur active « Nouvelle page depuis un modèle » (à la racine, ou sur une page pour une sous-page) et choisit un modèle, LE SYSTÈME DOIT créer une page ordinaire en dernière position sous le parent visé (F-002-AC5), dont le titre est celui du modèle et dont le contenu est la copie du contenu du modèle, la déplier, la sélectionner et l'ouvrir dans l'éditeur ; la copie DOIT être complète : un test énumère les types de bloc de la dernière ligne de `TABLE_DES_VERSIONS_PAGE` et les marques de F-028 (liens compris) et échoue si l'un d'eux n'est pas copié à l'identique.
    - F-044-AC4 : QUAND la page créée depuis un modèle est modifiée, LE SYSTÈME DOIT laisser le modèle intact ; QUAND le modèle est modifié ensuite, LE SYSTÈME DOIT laisser intactes les pages déjà créées depuis lui.
    - F-044-AC5 : QUAND le contenu copié porte, dans le document du modèle, une version de format du document de page supérieure à 1 (par exemple après l'ajout d'un bloc code, F-005), LE SYSTÈME DOIT élever la version du document de la nouvelle page au moins à celle du modèle, avant d'y écrire, de sorte qu'une application plus ancienne la refuse (ADR-0009).
    - F-044-AC6 : SI le contenu du modèle n'est pas disponible sur l'appareil (jamais ouvert ici et synchronisation indisponible, ou document refusé pour sa version), ALORS LE SYSTÈME DOIT ne créer aucune page, ne rien écrire et annoncer « Le modèle n'est pas disponible sur cet appareil » ; la commande « Nouvelle page depuis un modèle » DOIT rester utilisable pour les autres modèles.
    - F-044-AC7 : QUAND un modèle est ouvert dans l'éditeur, LE SYSTÈME DOIT l'y signaler par un bandeau « Modèle » qui ne repose pas sur la couleur seule, et le titre, le contenu et le renommage DOIVENT s'y modifier comme sur une page ordinaire (F-003, F-002-AC6).
    - F-044-AC8 : QUAND l'utilisateur met un modèle à la corbeille, LE SYSTÈME DOIT le retirer de la section « Modèles » et le faire apparaître dans l'écran de la corbeille avec une marque et un nom accessible qui commence par « Modèle » ; sa restauration DOIT le remettre dans la section « Modèles » et jamais dans l'arborescence, et sa suppression définitive DOIT effacer sa base de page comme celle d'une page (F-007, F-018-AC49). Les pages déjà créées depuis lui NE DOIVENT PAS être touchées.
    - F-044-AC9 : QUAND un membre d'un espace synchronisé crée, renomme ou retire un modèle de page, LE SYSTÈME DOIT le faire voir, après synchronisation, dans la section « Modèles » de tous les membres, et deux membres qui créent chacun un modèle hors ligne DOIVENT en retrouver deux après convergence, dans le même ordre.
    - F-044-AC10 : SI F-013 est livrée, ALORS, TANT QUE l'espace est ouvert en lecture seule (F-013-AC25), LE SYSTÈME DOIT désactiver, avec la raison « Lecture seule », « Nouveau modèle de page », « Enregistrer comme modèle », « Nouvelle page depuis un modèle » et la mise à la corbeille d'un modèle, et laisser la section « Modèles » consultable.
    - F-044-AC11 : SI le titre d'un modèle dépasse la limite de titre d'une page (200 unités UTF-16, F-001), ALORS LE SYSTÈME DOIT refuser comme pour une page ; SI le document d'espace contient une entrée de modèle mal formée (champ de marque de mauvais type), ALORS LE SYSTÈME DOIT la lire comme une page ordinaire de l'arborescence ou l'ignorer, selon la règle fixée par la conception (H3), sans lever d'exception et de la même façon sur toutes les répliques.
  - Modèles de ligne de table
    - F-044-AC12 : QUAND l'utilisateur ouvre « Modèles de ligne » depuis l'écran d'une table qui a au moins une colonne, LE SYSTÈME DOIT présenter la liste des modèles de ligne de la table dans leur ordre, avec « Nouveau modèle » ; SI la table n'a aucune colonne, LE SYSTÈME DOIT désactiver la commande avec la raison « Ajoutez d'abord une colonne ».
    - F-044-AC13 : QUAND l'utilisateur active « Nouveau modèle de ligne » et donne un nom, LE SYSTÈME DOIT créer le modèle, sans valeur par défaut, en dernière position, par une seule opération du document de table, et ouvrir son édition.
    - F-044-AC14 : QUAND l'utilisateur modifie les valeurs par défaut d'un modèle, LE SYSTÈME DOIT présenter un champ par colonne, de même nature que la cellule (texte, nombre, case, date, sélection, et étiquettes si F-045 est livrée, avec leurs règles de saisie et d'annonce : F-018-AC26 à AC31), écrire la valeur dans le modèle par une seule opération, et ne modifier aucune ligne de la table.
    - F-044-AC15 : QUAND l'utilisateur renomme un modèle de ligne, le supprime (après confirmation), ou le déplace, LE SYSTÈME DOIT exposer le nouvel état sans toucher aux lignes déjà créées depuis lui ; un modèle supprimé DOIT disparaître de la liste sans être effacé du document (même règle que les colonnes et les lignes, F-017 H5).
    - F-044-AC16 : QUAND l'utilisateur ouvre le menu de « Nouvelle ligne » et choisit « Depuis un modèle » puis un modèle, LE SYSTÈME DOIT créer une ligne en dernière position par une seule opération du document de table, avec les valeurs par défaut du modèle conformes à leur colonne et les autres cellules vides, l'amener dans la fenêtre et placer le focus sur sa première cellule (F-018-AC23) ; la table lue et les abonnés DOIVENT voir une création de ligne, pas une création puis des écritures.
    - F-044-AC17 : SI une valeur par défaut désigne une colonne supprimée, une option retirée ou n'est plus conforme au type de sa colonne, ALORS LE SYSTÈME DOIT la lire vide dans le modèle, la signaler comme inactive dans l'édition du modèle, et ne pas l'écrire dans la ligne créée, sans lever d'exception et de la même façon sur toutes les répliques.
    - F-044-AC18 : SI une valeur par défaut ne respecte pas le type de sa colonne (mêmes règles que F-017-AC18), si le nom d'un modèle dépasse 200 caractères, si le modèle ou la colonne visés sont absents ou supprimés, ALORS LE SYSTÈME DOIT refuser par une erreur typée et n'émettre aucune mise à jour Yjs ; un nom vide DOIT être accepté et affiché « Sans titre ».
    - F-044-AC19 (couture de « Nouvelle ligne ») : QUAND une table n'a aucun modèle de ligne, LE SYSTÈME DOIT afficher « Nouvelle ligne » et se comporter exactement comme avant (F-018-AC23) ; QUAND elle en a, la commande principale DOIT garder ce comportement (ligne vide) et le menu DOIT s'y ajouter ; les tests de F-018 qui créent une ligne DOIVENT passer sans modification (H10).
    - F-044-AC20 : QUAND deux répliques créent chacune un modèle de ligne, ou modifient chacune une valeur par défaut différente du même modèle, puis convergent, LE SYSTÈME DOIT conserver tous les modèles et les deux valeurs ; pour la même valeur, la dernière écriture gagne (F-017 H6) ; QUAND une réplique supprime un modèle pendant que l'autre le modifie ou crée une ligne depuis lui, LE SYSTÈME DOIT le lire supprimé sur les deux et conserver la ligne créée.
    - F-044-AC21 : SI F-013 est livrée, ALORS, TANT QUE l'espace est ouvert en lecture seule (F-013-AC25), LE SYSTÈME DOIT désactiver, avec la raison « Lecture seule », la création, la modification et la suppression d'un modèle de ligne ainsi que « Depuis un modèle » ; la liste DOIT rester consultable.
  - Format et coutures
    - F-044-AC22 (format de la table) : QUAND le premier modèle de ligne est créé dans un document de table, LE SYSTÈME DOIT élever dans la même transaction la version de format du document à la version suivante de celle que F-045 a livrée, sous une forme stockée telle qu'une application plus ancienne refuse le document entier au lieu d'ignorer les modèles ou de refuser le type racine inconnu sans le dire ; LE SYSTÈME DOIT lire et écrire comme avant un document qui n'a aucun modèle, sans l'élever, et refuser par `version-non-prise-en-charge` toute version lue supérieure à celle qu'il connaît.
    - F-044-AC23 (document de table lu) : LE SYSTÈME DOIT garder la forme de la table lue (`colonnes`, `lignes`) inchangée ; les modèles de ligne DOIVENT se lire par une lecture distincte ; un test DOIT comparer la table lue d'un document avec et sans modèles.
    - F-044-AC24 (couture des appelants) : QUAND le contrat public de `@notionlike/document` s'élargit (nouvelles opérations, nouveaux types, nouveaux codes d'erreur, nouvelle entrée du document d'espace), un test de couture DOIT comparer la liste des exports et celle des codes d'erreur aux listes attendues (F-017-AC25) et énumérer les paquets du workspace qui dépendent de `@notionlike/document` pour échouer si l'un d'eux ne passe pas sa vérification de types et ses tests.
    - F-044-AC25 (couture de l'arborescence) : LE SYSTÈME DOIT garder l'arborescence lue du document d'espace sans modèle de page : ni la barre latérale, ni le glisser-déposer (F-006), ni la corbeille des pages, ni le calcul de rang, ni le changement de parent ne DOIVENT pouvoir viser un modèle ; un test énumère les appelants de la lecture de l'arborescence dans `apps/web/src` et vérifie qu'aucun ne reçoit de modèle.
    - F-044-AC26 (liste fermée des tests existants) : LE SYSTÈME DOIT laisser passer sans modification tous les tests des features livrées, SAUF ceux de la liste de H10, dont seule la valeur qui figeait la liste des exports, des codes d'erreur ou des versions refusées peut changer.
    - F-044-AC27 (bout en bout) : QUAND la commande de test de bout en bout est lancée, LE SYSTÈME DOIT dérouler dans un navigateur réel le scénario : écrire une page de trois blocs (titre, paragraphe en gras, liste), l'enregistrer comme modèle, créer une page depuis ce modèle et constater les mêmes blocs ; dans une table de deux colonnes, créer un modèle de ligne avec une valeur par défaut, créer une ligne depuis lui et constater la valeur ; recharger la page et retrouver le modèle de page, la page créée, le modèle de ligne et la ligne.
- Hors périmètre (explicitement) :
  - Modèles de base de données entière (dupliquer une table avec ses colonnes, ses options, ses lignes et ses vues, ou « créer une table depuis un modèle ») : voir H1.
  - Sous-pages d'un modèle de page : la copie ne porte que le contenu de la page, pas ses sous-pages (H4).
  - Modèle de ligne portant du contenu de page (le corps d'une ligne ouverte comme une page n'existe pas, F-017) ; dates relatives (« aujourd'hui », « maintenant »), personne, formules ; modèle appliqué automatiquement ; modèle par défaut d'une table (bouton « Nouveau » qui l'applique) ; répétition.
  - Modèles propres à un membre ou à un dossier ; galerie de modèles livrée avec l'application ; import ou export de modèles ; recherche dans les modèles.
  - Création d'une carte du kanban depuis un modèle (F-020) ; création d'une ligne depuis un modèle au clavier hors du menu de « Nouvelle ligne » ; palette de commandes (F-024).
  - Bloc ou commande slash « insérer un modèle » dans une page (`edition/`, F-040 à F-042).
  - Duplication d'une page ordinaire (sans passer par un modèle) : hors lot, voir H1.
- Hypothèses proposées, que la validation de cette spec entérine (le dev tranche) :
  - H1 — À trancher : périmètre de la feature. Recommandé : modèles de page (« Enregistrer comme modèle », section « Modèles », « Nouvelle page depuis un modèle ») ET modèles de ligne de table (« Nouvelle ligne depuis un modèle » avec valeurs par défaut), parce que ce sont les deux usages que le dev a vus dans Notion et que les deux s'appuient sur des documents déjà livrés (page, table). Les modèles de base de données entière (copier une table avec colonnes, options et lignes) sont hors périmètre : ils touchent la création d'une table (F-018-AC10), les vues et les réglages de vue de l'appareil, et sont à planifier à part. Autres choix possibles : (a) modèles de page seuls, (b) modèles de ligne seuls, (c) ajouter la duplication simple d'une page (« Dupliquer », qui n'existe pas aujourd'hui), faisable avec le mécanisme de copie de F-044-AC3. La feature est grosse (deux formats de document touchés, deux interfaces) : la conception DOIT proposer un découpage en blocs livrables (page, puis ligne) ; si elle juge qu'une session ne suffit pas, la spec est scindée (F-044 pages, nouvelle feature pour les lignes), donc à revalider.
  - H2 — Un modèle de page est une entrée du document d'espace marquée par un champ propre (`modele`), qui n'apparaît pas dans l'arborescence lue : le contenu du modèle est un document de page ordinaire (même base, mêmes droits, même synchronisation, même corbeille). Choix retenu parce qu'il réutilise l'éditeur, la persistance, la synchronisation et la corbeille sans duplication. Alternative écartée : un document dédié aux modèles de l'espace (second document par espace, nouvelle autorisation côté serveur).
  - H3 — À confirmer par la conception : faut-il élever la version du document d'espace (3) ? Le champ `modele` est un champ inconnu qu'ADR-0002 fait ignorer : une application plus ancienne verrait le modèle comme une page ordinaire de la racine, sans perte de données. Recommandé : ne pas élever la version (dégradation acceptable, aucun changement de contrat de synchronisation). Si la conception conclut le contraire (par exemple pour qu'une ancienne application ne déplace pas un modèle dans l'arborescence), la spec est retouchée : lignes Revue et Agents (`reviewer-backend`, `reviewer-api`, `agent-backend`), `VERSION_DU_DOCUMENT_D_ESPACE` de `packages/contrats` et son garde côté serveur (F-018-AC57, AC58) ; donc à revalider. F-044-AC11 en fixe le repli de lecture.
  - H4 — Une page créée depuis un modèle reçoit le titre du modèle (qui peut être vide) et une copie de son seul contenu ; ni les sous-pages, ni les commentaires (F-016), ni les images (F-022) ne sont copiés. La copie ne conserve aucun identifiant interne partagé avec le modèle. La conception dit comment un bloc est copié d'un `Y.Doc` à l'autre (copie du fragment, ou rejeu des opérations) et ce qu'il advient des identifiants de blocs.
  - H5 — Un modèle de page non disponible localement ne se crée pas (F-044-AC6) : la copie lit le document du modèle sur l'appareil, elle n'attend pas le réseau. Sur un appareil qui n'a jamais ouvert le modèle, la lecture passe par la synchronisation quand elle est disponible (F-013).
  - H6 — Les modèles de ligne vivent dans le document de la table qu'ils servent (ils se synchronisent avec elle, sans nouveau document ni nouveau droit). C'est un changement de format de ce document, donc une version : F-044 vient après F-045 (version 2) et prend la suivante (F-044-AC22), d'où la dépendance. Si F-045 n'est pas livrée avant, la spec est retouchée pour que F-044 livre la version 2 (revalidation).
  - H7 — Une valeur par défaut est une valeur de cellule (F-017) : un modèle ne peut pas contenir plus que ce que contient une ligne. Les colonnes `etiquettes` y sont admises si F-045 est livrée (c'est la raison de la dépendance) ; sinon la liste des types admis se limite aux cinq de F-017.
  - H8 — « Depuis un modèle » est un second geste (menu de « Nouvelle ligne ») plutôt qu'un modèle par défaut qui change le comportement du bouton : F-018-AC23 reste vrai pour tous les utilisateurs existants (F-044-AC19). Notion applique un modèle par défaut : reporté.
  - H9 — Pas de limite au nombre de modèles de page ni de ligne dans le format ; un nom de modèle de ligne comme un titre de page est limité à 200 unités UTF-16 (F-001, F-017 H8).
  - H10 — Liste fermée provisoire des tests d'autres features à modifier, relevée le 2026-10-30 sur `origin/main` (`a64bf5f`), à figer par la conception (écart documenté, comme F-020 H12) ; seule la valeur qui figeait un nombre d'exports, une liste de codes d'erreur ou une version refusée y change :
    - F-001 (`packages/document/test/`) : `corbeille.test.ts` (`EXPORTS_ATTENDUS` l.394, `CODES_ATTENDUS` l.439), `structure.test.ts`, `robustesse.test.ts` (tableau des versions non prises en charge, seulement si H3 élève la version du document d'espace).
    - F-017 (`packages/document/test/`) : `table-contrat.test.ts`, `table-lecture.test.ts` (versions refusées de F-017-AC22), `aides-table.ts`.
    - F-018 (`apps/web/test/`) : `vues-de-table/structure.test.ts` (liste des modules de `vues-de-table/`) ; les tests de création d'une ligne (F-018-AC23), de la barre latérale (F-002, F-018-AC11) et de la corbeille (F-007) doivent passer inchangés (F-044-AC19, AC25).
    - F-019 (`apps/web/test/vues-de-table/`) : aucun test attendu à modifier ; `lignes-affichees.test.tsx` et `filtres-et-tris.test.ts` doivent passer inchangés puisque la table lue ne change pas (F-044-AC23).
    - F-006 et F-007 (`apps/web/test/`) : les tests du glisser-déposer et de la corbeille doivent passer inchangés (F-044-AC25) ; l'ajout d'une marque « Modèle » dans la corbeille est une extension de F-007, à justifier test par test par la conception.
  - H11 — Conflits avec les branches en cours (ordre d'intégration, sans dépendance de code) : F-034 change `packages/document/src/document-table.ts` ; F-021 ajoute à `apps/web/src/vues-de-table/` ; F-038 et F-039 (tables, specs en cours d'écriture) peuvent toucher aux mêmes fichiers et au même numéro de version du document de table ; F-040 à F-042 changent `apps/web/src/edition/` : cette feature n'y touche pas (hors périmètre : bloc « insérer un modèle »), mais la copie de contenu de F-044-AC3 lit le schéma de l'éditeur (`TABLE_DES_VERSIONS_PAGE`) que ces features peuvent faire grandir ; la conception relit leurs specs avant de figer l'énumération de F-044-AC3. Cette feature se code après F-045 (version du document de table), F-034 et F-021.
  - H12 — Conception requise avant le code (agent-architecte-conception, ADR) : amendement de l'ADR-0002 (champ `modele` du document d'espace, lecture de l'arborescence sans modèles, choix de H3), amendement de l'ADR-0016 (version suivante, racine `modeles`, forme stockée), copie d'un document de page (ADR-0009), emplacement des modules dans `apps/web` (modèles de page : `navigation`/`page`; modèles de ligne : `vues-de-table`), découpage en blocs (H1). Aucune nouvelle dépendance directe attendue ; agent-veille sur déclencheur seulement.
  - H13 — Ne pas reprendre le vocabulaire « template » dans l'interface : « Modèle », comme le reste de l'interface en français.
- Prérequis à la charge du dev (fichiers refusés à un agent) : aucun nouveau paquet de workspace ni dépendance directe attendus ; si H3 élève la version du document d'espace, `packages/contrats` et le garde de `apps/server` changent (fichiers partagés, à signaler) ; `.dependency-cruiser.cjs` seulement si la conception propose une règle nouvelle.
- Pourquoi ce tier : deux changements de format de document (champ du document d'espace, version et racine du document de table), élargissement du contrat public de `@notionlike/document`, copie de contenu entre documents Yjs et nouveau flux de création de pages ; en cas de doute entre deux tiers, le plus élevé.
- Agents : agent-architecte-conception, agent-frontend (agent-veille sur déclencheur ; agent-backend seulement si H3 élève la version du document d'espace)
- Dépend de : F-045 (version du document de table, valeurs par défaut des étiquettes), F-002, F-003, F-007, F-017, F-018 (livrées) ; ordre d'intégration après F-034 et F-021 (H11)
