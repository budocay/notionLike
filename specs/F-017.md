# SPEC F-017 — Modèle de table (Yjs, `packages/document`) : colonnes typées, lignes, cellules

Statut : brouillon
Tier : structurel
Revue : reviewer-frontend

- Objectif (une phrase, côté métier) : une équipe tient une table (colonnes typées, lignes, valeurs) sur son appareil, sans réseau, et deux appareils qui ont travaillé séparément retrouvent la même table dès qu'ils échangent leurs modifications.
- Vocabulaire :
  - « document de table » : le document Yjs qui porte une table et une seule : ses colonnes, ses lignes et les valeurs de ses cellules (ADR-0001). Il ne porte ni titre, ni identifiant de table, ni vue.
  - « colonne » : un identifiant, un nom, un type fixé à la création et un rang parmi les colonnes. Types : `texte`, `nombre`, `case` (case à cocher), `date`, `selection` (un choix parmi les options de la colonne).
  - « option » : un choix d'une colonne `selection` : un identifiant et un libellé, ordonnés.
  - « ligne » : un identifiant, un rang parmi les lignes et, pour chaque colonne, une cellule.
  - « cellule » : la valeur d'une ligne pour une colonne ; elle est vide ou conforme au type de la colonne.
  - « table lue » : la vue en lecture que le module calcule à partir du document de table (colonnes et lignes non supprimées, ordonnées, avec leurs cellules).
  - « réplique », « converger », « erreur typée » : définis par `specs/F-001.md`.
- Critères d'acceptation :
  - Opérations locales
    - F-017-AC1 : QUAND un appelant crée un document de table, LE SYSTÈME DOIT fournir un document Yjs dont la table lue n'a ni colonne ni ligne et dont la version de format vaut 1.
    - F-017-AC2 : QUAND un appelant crée une colonne avec un nom et un type, LE SYSTÈME DOIT renvoyer un identifiant unique dans le document et faire apparaître la colonne dans la table lue à la position demandée, ou en dernière position si aucune n'est demandée ; les cellules de cette colonne DOIVENT se lire vides pour toutes les lignes.
    - F-017-AC3 : QUAND un appelant crée une ligne, avec ou sans valeurs initiales, LE SYSTÈME DOIT renvoyer un identifiant unique dans le document et faire apparaître la ligne à la position demandée, ou en dernière position si aucune n'est demandée, avec les valeurs fournies et les autres cellules vides.
    - F-017-AC4 : QUAND un appelant écrit une valeur conforme au type de la colonne dans une cellule, ou la vide, LE SYSTÈME DOIT exposer cette valeur (ou une cellule vide) dans la table lue sans changer aucune autre cellule.
    - F-017-AC5 : QUAND un appelant renomme une colonne, LE SYSTÈME DOIT exposer le nouveau nom sans changer ni le type, ni la position, ni les cellules de la colonne.
    - F-017-AC6 : QUAND un appelant déplace une colonne ou une ligne vers une autre position, LE SYSTÈME DOIT l'exposer à cette position sans changer l'ordre relatif des autres, ni aucune cellule.
    - F-017-AC7 : QUAND un appelant supprime une colonne ou une ligne, LE SYSTÈME DOIT la retirer de la table lue, avec ses cellules, sans l'effacer du document.
    - F-017-AC8 : QUAND un appelant ajoute, renomme, déplace ou retire une option d'une colonne `selection`, LE SYSTÈME DOIT exposer la liste d'options à jour, dans l'ordre demandé ; les cellules qui portaient une option retirée DOIVENT se lire vides.
    - F-017-AC9 : QUAND la table lue change, par une opération locale ou par l'application d'une mise à jour Yjs reçue, LE SYSTÈME DOIT notifier chaque abonné une fois par transaction Yjs, ne pas le notifier pour une transaction qui ne change pas la table lue, et ne plus le notifier après son désabonnement.
  - Convergence entre répliques
    - F-017-AC10 : QUAND deux répliques ont appliqué des opérations différentes sans se voir puis convergent, quel que soit l'ordre d'application des mises à jour, LE SYSTÈME DOIT lire sur les deux la même table (mêmes colonnes, mêmes options, mêmes lignes, même ordre, mêmes cellules).
    - F-017-AC11 : QUAND deux répliques écrivent chacune une cellule différente de la même ligne puis convergent, LE SYSTÈME DOIT conserver les deux valeurs.
    - F-017-AC12 : QUAND deux répliques écrivent des valeurs différentes dans la même cellule puis convergent, LE SYSTÈME DOIT exposer sur les deux la même valeur, égale à l'une des deux.
    - F-017-AC13 : QUAND deux répliques créent chacune une ligne (ou chacune une colonne) à la même position puis convergent, LE SYSTÈME DOIT conserver les deux et les présenter dans le même ordre sur les deux répliques.
    - F-017-AC14 : QUAND une réplique supprime une ligne ou une colonne pendant que l'autre écrit dans l'une de ses cellules, la renomme ou la déplace, puis qu'elles convergent, LE SYSTÈME DOIT la lire supprimée sur les deux répliques, sans lever d'exception.
    - F-017-AC15 : QUAND une réplique retire une option pendant que l'autre l'affecte à une cellule, puis qu'elles convergent, LE SYSTÈME DOIT lire l'option absente et cette cellule vide sur les deux répliques.
    - F-017-AC16 : QUAND l'état complet d'un document de table est encodé en une mise à jour Yjs (format V1) puis appliqué à un document vierge, LE SYSTÈME DOIT lire sur ce document la même table que sur l'original.
  - Erreurs et limites
    - F-017-AC17 : SI une opération vise un identifiant de colonne, de ligne ou d'option absent du document ou supprimé, ALORS LE SYSTÈME DOIT refuser par une erreur typée et n'émettre aucune mise à jour Yjs.
    - F-017-AC18 : SI une valeur n'est pas conforme au type de la colonne (texte de plus de 2 000 caractères ; nombre non fini ; valeur non booléenne pour `case` ; date qui n'est pas une date du calendrier au format `AAAA-MM-JJ` ; identifiant qui n'est pas une option de la colonne), ALORS LE SYSTÈME DOIT refuser l'écriture par une erreur typée et n'émettre aucune mise à jour Yjs ; un texte vide et le nombre 0 DOIVENT être acceptés et se lire tels quels.
    - F-017-AC19 : SI un nom de colonne dépasse 200 caractères, si un libellé d'option dépasse 100 caractères, si le type demandé n'est pas l'un des cinq types, ou si une position n'est pas un entier compris entre 0 et le nombre d'éléments de destination, ALORS LE SYSTÈME DOIT refuser par une erreur typée et n'émettre aucune mise à jour Yjs ; un nom et un libellé vides DOIVENT être acceptés.
    - F-017-AC20 : SI le document contient une colonne, une option ou une ligne mal formée (champ manquant ou de mauvais type, type de colonne inconnu, nom ou libellé trop long), ALORS LE SYSTÈME DOIT l'ignorer à la lecture sans lever d'exception et continuer d'exposer le reste de la table.
    - F-017-AC21 : SI une cellule enregistrée n'est pas conforme au type de sa colonne, désigne une option absente, ou se rattache à une colonne absente, supprimée ou ignorée au titre de F-017-AC20, ALORS LE SYSTÈME DOIT la lire vide (ou ne pas l'exposer, faute de colonne) sans lever d'exception, de la même façon sur toutes les répliques.
    - F-017-AC22 : SI la version de format du document de table est supérieure à celle que le module connaît, ALORS LE SYSTÈME DOIT refuser la lecture et toute écriture par une erreur typée dédiée, sans modifier le document.
    - F-017-AC23 : SI un appelant ouvre comme table un document produit par `creerDocumentEspace`, ALORS LE SYSTÈME DOIT refuser la lecture et toute écriture par une erreur typée dédiée, sans modifier le document ; un document Yjs vierge, en attente de son contenu, DOIT s'ouvrir et se lire comme une table sans colonne ni ligne.
  - Structure et coutures
    - F-017-AC24 : LE SYSTÈME DOIT s'exécuter sous Node sans DOM, sans réseau et sans stockage, garder `yjs` pour seule dépendance d'exécution directe de `packages/document`, n'exposer aucun type Yjs autre que `Y.Doc`, et `pnpm contrats` DOIT finir sans violation.
    - F-017-AC25 (couture de l'interface de F-001) : LE SYSTÈME DOIT laisser inchangés les exports livrés par F-001 (mêmes noms, mêmes signatures, mêmes codes d'erreur pour les mêmes refus) et le format du document d'espace ; un test DOIT comparer la liste des exports du paquet à la liste attendue (ceux de F-001 plus ceux de cette spec) et la liste des codes d'erreur à la liste attendue, et un test de couture DOIT énumérer les paquets du workspace qui dépendent de `@notionlike/document` et échouer si l'un d'eux ne passe pas sa vérification de types et ses tests avec les codes d'erreur ajoutés.
- Hors périmètre (explicitement) :
  - Toute interface (vue tableau : F-018 ; filtres et tris : F-019 ; kanban : F-020 ; calendrier : F-021) et toute configuration de vue enregistrée dans le document : les features de vue décideront où elle vit.
  - Persistance (F-018, selon la convention de nommage de F-002), réseau, serveur, autorisation (F-012).
  - Rattachement d'une table à l'arborescence des pages : le document d'espace n'est pas modifié ici (voir H2) ; F-018 le spécifiera, avec le test de couture du format du document d'espace.
  - Changement de type d'une colonne ; duplication de colonne ou de ligne ; restauration d'une colonne ou d'une ligne supprimée ; effacement réel (F-025).
  - Autres types : sélection multiple, relation entre tables, formule, personne, lien, fichier, date avec heure ou fuseau, intervalle de dates ; couleur d'une option ; format d'affichage d'un nombre ; largeur et visibilité d'une colonne.
  - Fusion caractère par caractère d'un texte de cellule ; une ligne ouverte comme une page ; commentaires sur une ligne.
  - Tri, filtre, regroupement, agrégats : calculés par les vues, pas par le modèle. L'ordre des lignes de la table lue est l'ordre manuel.
  - Limite de taille et objectif de performance chiffré (voir H8).
  - Migration de format : il n'existe qu'une version (1) du document de table ; F-017-AC22 ne fait que refuser une version inconnue.
- Hypothèses proposées, que la validation de cette spec entérine (le dev tranche) :
  - H1 — Un document Yjs par table (ADR-0001), avec sa propre version de format, indépendante de celle du document d'espace.
  - H2 — Le document de table ne porte ni son identifiant ni son titre. Cible retenue pour F-018 : une table est une page de l'arborescence, l'identifiant de la table est celui de cette page et son titre est le titre de la page. Difficile à défaire une fois des tables enregistrées.
  - H3 — Cinq types de colonne, ceux qu'exigent les vues de la fiche (tableau, kanban par `selection`, calendrier par `date`, filtres et tris). Le type est fixé à la création : convertir des valeurs pendant que deux répliques écrivent n'a pas de résultat évident, et supprimer puis recréer une colonne suffit à ce stade.
  - H4 — Une date est un jour du calendrier (`AAAA-MM-JJ`), sans heure ni fuseau : deux appareils de fuseaux différents lisent le même jour.
  - H5 — Supprimer une colonne ou une ligne pose un drapeau, comme la corbeille des pages (ADR-0002) : rien n'est effacé, le résultat d'une suppression simultanée à une écriture est déterministe (F-017-AC14), et une restauration reste possible plus tard. Le document ne rétrécit donc jamais. Difficile à défaire : c'est le format.
  - H6 — Dernière écriture gagne par cellule, par nom de colonne et par libellé d'option (F-017-AC12) ; un texte de cellule est une valeur simple, pas un texte collaboratif.
  - H7 — Une table naît sans colonne ; aucune colonne n'est obligatoire ni protégée, car deux répliques qui suppriment chacune une colonne différente rendraient intenable toute règle « au moins une colonne ». Les vues choisiront la colonne qui sert de titre (F-018, F-020).
  - H8 — Limites : nom de colonne de 200 caractères au plus, libellé d'option de 100, texte de cellule de 2 000, mesurés en unités UTF-16 comme les titres de page ; aucune limite au nombre de colonnes, d'options ou de lignes. Usage visé : quelques milliers de lignes par table, sans objectif chiffré dans cette feature.
  - H9 — L'ordre des colonnes, des options et des lignes suit la même règle que les pages sœurs (rang, puis identifiant pour départager) ; le calcul des rangs de F-001 est réutilisé à l'intérieur du paquet, sans être exporté.
  - H10 — Interface publique, par le point d'entrée existant de `@notionlike/document` (pas de sous-chemin) : `creerDocumentTable()`, `ouvrirDocumentTable(doc)`, une façade `DocumentTable` (document Yjs, lecture en instantané immuable, abonnement, opérations), sur le modèle de `DocumentEspace`. `ouvrirDocumentTable` n'écrit rien.
  - H11 — Les refus passent par la classe `ErreurDocument` existante : les codes déjà publiés sont repris pour les mêmes refus (position invalide, version non prise en charge) et de nouveaux codes s'y ajoutent. Élargir cette liste est un changement de contrat public, d'où F-017-AC25.
  - H12 — La lecture d'une cellule vide est une valeur d'absence unique, distincte du texte vide, de 0 et de `false`.
- Prérequis à la charge du dev (fichiers refusés à un agent, texte exact fourni par `agent-architecte-conception`) :
  - F-001 livrée et fusionnée : squelette de `packages/document`, `yjs` et `fast-check` déjà installés.
  - Aucun nouveau paquet de workspace, aucune nouvelle dépendance directe, aucun changement de `package.json` ni de `vitest.config.*` attendu. Playwright et Stryker ne sont pas requis.
  - `.dependency-cruiser.cjs` (fichier protégé), seulement si la conception propose une règle nouvelle pour les fichiers du modèle de table.
  - Si F-002 est livrée avant cette feature, `apps/web` fait partie des paquets énumérés par F-017-AC25.
- Pourquoi ce tier : naissance d'un second format de document, que le client et le serveur consommeront et qui se défait mal, et élargissement du contrat public de `@notionlike/document` (nouveaux exports, nouveaux codes d'erreur).
- Agents : agent-veille (Yjs 13, rafraîchissement), agent-architecte-conception, agent-frontend
- Dépend de : F-001
