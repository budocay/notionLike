# SPEC F-055 — Pile Docker : `PGPASSWORD` hors de l'environnement du client `docker` (D-031) et plancher de Compose (D-030)

Statut : validée
Tier : structurel
Revue : reviewer-devops

- Objectif (une phrase, côté métier) : la commande qui éprouve le mot de passe de la base ne laisse ce mot de passe ni dans l'environnement ni dans les arguments d'un processus visible du poste, et la pile refuse une version de Compose dont le comportement n'est pas prouvé.
- Origine : D-031 (`PGPASSWORD` dans l'environnement du client `docker` le temps de l'épreuve, CWE-214, F-031) et D-030 (Compose 2.24.0 à 2.24.3 admises sans preuve), décision du dev du 2026-11-02 (Q9 : plancher 2.24.4 si publiée, vérifié plus tard par agent-veille, sinon la plage actuelle est acceptée et D-030 close). Q10 : D-032 (origine Playwright 5174) acceptée, hors de cette feature. Site : `infra/pile.sh:536-537` (`PGPASSWORD="$MOT_DE_PASSE"; export PGPASSWORD`).
- Vocabulaire : « épreuve du mot de passe » : l'étape de `pile.sh accorder`/`demarrer` qui se connecte à la base avec le mot de passe de `infra/.env` (F-031) ; « processus visible » : visible par `ps` et `/proc/<pid>/environ` pour un autre utilisateur du poste ; « plancher » : version minimale de Compose acceptée par `pile.sh`.
- Critères d'acceptation :
  - F-055-AC1 : QUAND `pile.sh` éprouve le mot de passe, LE SYSTÈME DOIT NE PAS exporter `PGPASSWORD` dans l'environnement du processus `docker` qu'il lance (H1).
  - F-055-AC2 : QUAND l'épreuve s'exécute, LE SYSTÈME DOIT NE PAS faire apparaître le mot de passe dans les arguments du processus `docker` ni dans ceux de `psql`.
  - F-055-AC3 : QUAND le mot de passe est correct, LE SYSTÈME DOIT conclure comme avant (même message, même code de sortie 0) ; SI le mot de passe est faux, ALORS il DOIT conclure comme avant (même message qui ne contient pas la valeur, même code de sortie non nul).
  - F-055-AC4 : QUAND l'épreuve échoue de façon inattendue (conteneur arrêté, `psql` absent), LE SYSTÈME DOIT NE JAMAIS écrire la valeur du mot de passe sur la sortie standard ni sur la sortie d'erreur.
  - F-055-AC5 : QUAND un test de `infra/tests/` remplace `docker` par un exécutable factice qui enregistre son environnement et ses arguments, LE SYSTÈME DOIT y trouver ni la variable `PGPASSWORD` ni la valeur du mot de passe (cas fautif donné comme donnée : l'ancien code y échoue).
  - F-055-AC6 : QUAND `pile.sh` est lancé, LE SYSTÈME DOIT continuer à retirer `PGPASSWORD` de l'environnement hérité (ligne 53 aujourd'hui) avant toute commande.
  - F-055-AC7 : QUAND le dev ou la CI lancent la fumée officielle de F-031 (AC27, AC28), LE SYSTÈME DOIT la passer sans modification de ses oracles.
  - F-055-AC8 : SI `agent-veille` atteste dans `MEMORY/VEILLE.md` que Compose 2.24.4 (ou plus) est publiée depuis plus de 7 jours, ALORS LE SYSTÈME DOIT refuser, avec un message qui cite la version trouvée et le plancher, toute version de Compose inférieure à 2.24.4 ; SI elle ne l'est pas, ALORS ce critère ne s'applique pas et D-030 est close par acceptation de la plage 2.24.0 à 2.24.3.
  - F-055-AC9 : SI shellcheck est activé dans `.agents/outils.env` (D-033, décision du dev), ALORS `infra/pile.sh` et `infra/fumee.sh` DOIVENT le passer sans exemption écrite dans le code (les exemptions `nosemgrep` et `gitleaks:allow` sont ignorées par les contrôles).
  - F-055-AC10 : QUAND le contrôle de version de Compose est modifié, LE SYSTÈME DOIT avoir un test de couture qui énumère ses appelants (`pile.sh`, `fumee.sh`, `README.md` de prérequis, `ci.yml`) et échoue si la version minimale diffère de l'un à l'autre.
- Hypothèses (recommandation de la planification) :
  - H1 — Passage du mot de passe : recommandation, le lire sur l'entrée standard du processus `psql` du conteneur (`docker exec -i … sh -c 'PGPASSWORD=$(cat) exec psql …'`) plutôt que `-e PGPASSWORD`, de sorte qu'il n'est dans l'environnement que du processus du conteneur, jamais du client `docker` ; à confirmer par agent-architecte-conception si une autre voie (`PGPASSFILE` monté) est préférable.
  - H2 — Le plancher 2.24.4 n'est pas encore vérifié publié : recommandation, laisser AC8 conditionnelle, le dev ou agent-veille tranche à la validation de la feature.
  - H3 — L'ordre avec F-051 et F-052 (même `ci.yml`) : recommandation, F-055 ne touche pas `ci.yml` si le plancher n'y est pas lu ; sinon le dev commite la ligne de CI.
- Hors périmètre (explicitement) : D-032 (acceptée, risque local) ; D-033 en tant que décision (le dev ajoute shellcheck lui-même) ; le changement de mot de passe de la base ; le déploiement hors du poste du dev (TLS, proxy, sauvegarde).
- Pourquoi ce tier : modification d'un script d'infrastructure (`infra/pile.sh`) : infra = `structurel` (AGENTS.md) ; pas de dépendance directe nouvelle.
