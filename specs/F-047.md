# SPEC F-047 — Modèles de ligne : lignes de table pré-remplies

Statut : brouillon
Tier : structurel
Revue : reviewer-frontend

- Objectif (une phrase, côté métier) : une équipe garde des modèles de ligne (une ligne de table pré-remplie) et crée une ligne depuis l'un d'eux en un geste, comme les « Templates » d'une base de données de Notion, sans réseau et avec les mêmes droits que le reste de l'espace.
- Origine : retour du dev sur la RC1 (2026-10-30, donnée) : « on ne peut pas créer de template, de labels etc etc je t'avais pourtant dit de t'inspirer de Notion ». Cette feature est la moitié « table » de la spec F-044, scindée sur la recommandation de la conception (`docs/decisions/F-044-conception.md`, « Recommandation : scinder la spec ») : F-044-AC12 à AC23 sont devenus F-047-AC1 à AC12 ; les modèles de page restent dans `specs/F-044.md`, les étiquettes dans `specs/F-045.md`.
- Vocabulaire :
  - « modèle de ligne » : un nom et, pour chaque colonne de la table, une valeur par défaut (vide ou conforme au type de la colonne). Il vit dans le document de la table qu'il sert ; il ne porte ni contenu de page (une ligne n'est pas une page, F-017) ni date relative.
  - « ligne créée depuis un modèle » : une ligne ordinaire dont les cellules ont, à la création, les valeurs par défaut du modèle ; ensuite, plus aucun lien.
  - « document de table », « table lue », « façade », « réplique », « converger », « erreur typée » : définis par `specs/F-001.md`, `specs/F-017.md`. « écran de table », « grille », « boîte » : `specs/F-018.md`. « colonne `etiquettes` » : `specs/F-045.md`.
- Critères d'acceptation :
  - Modèles de ligne de table
    - F-047-AC1 : QUAND l'utilisateur ouvre « Modèles de ligne » depuis l'écran d'une table qui a au moins une colonne, LE SYSTÈME DOIT présenter la liste des modèles de ligne de la table dans leur ordre, avec « Nouveau modèle » ; SI la table n'a aucune colonne, LE SYSTÈME DOIT désactiver la commande avec la raison « Ajoutez d'abord une colonne ».
    - F-047-AC2 : QUAND l'utilisateur active « Nouveau modèle de ligne » et donne un nom, LE SYSTÈME DOIT créer le modèle, sans valeur par défaut, en dernière position, par une seule opération du document de table, et ouvrir son édition.
    - F-047-AC3 : QUAND l'utilisateur modifie les valeurs par défaut d'un modèle, LE SYSTÈME DOIT présenter un champ par colonne, de même nature que la cellule (texte, nombre, case, date, sélection, et étiquettes si F-045 est livrée, avec leurs règles de saisie et d'annonce : F-018-AC26 à AC31), écrire la valeur dans le modèle par une seule opération, et ne modifier aucune ligne de la table.
    - F-047-AC4 : QUAND l'utilisateur renomme un modèle de ligne, le supprime (après confirmation), ou le déplace, LE SYSTÈME DOIT exposer le nouvel état sans toucher aux lignes déjà créées depuis lui ; un modèle supprimé DOIT disparaître de la liste sans être effacé du document (même règle que les colonnes et les lignes, F-017 H5).
    - F-047-AC5 : QUAND l'utilisateur ouvre le menu de « Nouvelle ligne » et choisit « Depuis un modèle » puis un modèle, LE SYSTÈME DOIT créer une ligne en dernière position par une seule opération du document de table, avec les valeurs par défaut du modèle conformes à leur colonne et les autres cellules vides, l'amener dans la fenêtre et placer le focus sur sa première cellule (F-018-AC23) ; la table lue et les abonnés DOIVENT voir une création de ligne, pas une création puis des écritures.
    - F-047-AC6 : SI une valeur par défaut désigne une colonne supprimée, une option retirée ou n'est plus conforme au type de sa colonne, ALORS LE SYSTÈME DOIT la lire vide dans le modèle, la signaler comme inactive dans l'édition du modèle, et ne pas l'écrire dans la ligne créée, sans lever d'exception et de la même façon sur toutes les répliques.
    - F-047-AC7 : SI une valeur par défaut ne respecte pas le type de sa colonne (mêmes règles que F-017-AC18), si le nom d'un modèle dépasse 200 caractères, si le modèle ou la colonne visés sont absents ou supprimés, ALORS LE SYSTÈME DOIT refuser par une erreur typée et n'émettre aucune mise à jour Yjs ; un nom vide DOIT être accepté et affiché « Sans titre ».
    - F-047-AC8 (couture de « Nouvelle ligne ») : QUAND une table n'a aucun modèle de ligne, LE SYSTÈME DOIT afficher « Nouvelle ligne » et se comporter exactement comme avant (F-018-AC23) ; QUAND elle en a, la commande principale DOIT garder ce comportement (ligne vide) et le menu DOIT s'y ajouter ; les tests de F-018 qui créent une ligne DOIVENT passer sans modification (H6).
    - F-047-AC9 : QUAND deux répliques créent chacune un modèle de ligne, ou modifient chacune une valeur par défaut différente du même modèle, puis convergent, LE SYSTÈME DOIT conserver tous les modèles et les deux valeurs ; pour la même valeur, la dernière écriture gagne (F-017 H6) ; QUAND une réplique supprime un modèle pendant que l'autre le modifie ou crée une ligne depuis lui, LE SYSTÈME DOIT le lire supprimé sur les deux et conserver la ligne créée.
    - F-047-AC10 : SI F-013 est livrée, ALORS, TANT QUE l'espace est ouvert en lecture seule (F-013-AC25), LE SYSTÈME DOIT désactiver, avec la raison « Lecture seule », la création, la modification et la suppression d'un modèle de ligne ainsi que « Depuis un modèle » ; la liste DOIT rester consultable.
  - Format et coutures
    - F-047-AC11 (format de la table) : QUAND le premier modèle de ligne est créé dans un document de table, LE SYSTÈME DOIT élever dans la même transaction la version de format du document à la version suivante de celle que F-045 a livrée, sous une forme stockée telle qu'une application plus ancienne refuse le document entier au lieu d'ignorer les modèles ou de refuser le type racine inconnu sans le dire ; LE SYSTÈME DOIT lire et écrire comme avant un document qui n'a aucun modèle, sans l'élever, et refuser par `version-non-prise-en-charge` toute version lue supérieure à celle qu'il connaît.
    - F-047-AC12 (document de table lu) : LE SYSTÈME DOIT garder la forme de la table lue (`colonnes`, `lignes`) inchangée ; les modèles de ligne DOIVENT se lire par une lecture distincte ; un test DOIT comparer la table lue d'un document avec et sans modèles.
    - F-047-AC13 (couture des appelants) : QUAND le contrat public de `@notionlike/document` s'élargit (nouvelles opérations, nouveaux types, nouveaux codes d'erreur), un test de couture DOIT comparer la liste des exports et celle des codes d'erreur aux listes attendues (F-017-AC25), compléter la liste fermée de `coutures-etiquettes.test.ts` (F-045-AC29) pour chaque source nouvelle qui lit `ValeurDeCellule` ou `.options`, et énumérer les paquets du workspace qui dépendent de `@notionlike/document` pour échouer si l'un d'eux ne passe pas sa vérification de types et ses tests.
    - F-047-AC14 (liste fermée des tests existants) : LE SYSTÈME DOIT laisser passer sans modification tous les tests des features livrées, SAUF ceux de la liste de H6, dont seule la valeur qui figeait la liste des exports, des codes d'erreur ou des versions refusées peut changer.
    - F-047-AC15 (bout en bout) : QUAND la commande de test de bout en bout est lancée, LE SYSTÈME DOIT dérouler dans un navigateur réel le scénario : dans une table de deux colonnes, créer un modèle de ligne avec une valeur par défaut, créer une ligne depuis lui et constater la valeur ; recharger la page et retrouver le modèle de ligne et la ligne.
- Hors périmètre (explicitement) :
  - Modèles de page : `specs/F-044.md`.
  - Modèles de base de données entière (dupliquer une table avec ses colonnes, ses options, ses lignes et ses vues, ou « créer une table depuis un modèle ») : voir H1.
  - Modèle de ligne portant du contenu de page (le corps d'une ligne ouverte comme une page n'existe pas, F-017) ; dates relatives (« aujourd'hui », « maintenant »), personne, formules ; modèle appliqué automatiquement ; modèle par défaut d'une table (bouton « Nouveau » qui l'applique) ; répétition.
  - Modèles propres à un membre ou à un dossier ; galerie de modèles livrée avec l'application ; import ou export de modèles ; recherche dans les modèles.
  - Création d'une carte du kanban depuis un modèle (F-020) ; création d'une ligne depuis un modèle au clavier hors du menu de « Nouvelle ligne » ; palette de commandes (F-024).
- Hypothèses proposées, que la validation de cette spec entérine (le dev tranche) :
  - H1 — Périmètre : les modèles de ligne seuls. La scission de F-044 est celle que recommande sa conception (deux formats de document, deux interfaces, une dépendance qui ne vaut que pour cette moitié) ; les modèles de base de données entière restent hors périmètre (F-044 H1).
  - H2 — Les modèles de ligne vivent dans le document de la table qu'ils servent (ils se synchronisent avec elle, sans nouveau document ni nouveau droit). C'est un changement de format de ce document, donc une version : F-047 vient après F-045 (version 2) et prend la suivante (F-047-AC11), d'où la dépendance. Si F-045 n'est pas livrée avant, la spec est retouchée pour que F-047 livre la version 2 (revalidation).
  - H3 — Une valeur par défaut est une valeur de cellule (F-017) : un modèle ne peut pas contenir plus que ce que contient une ligne. Les colonnes `etiquettes` y sont admises si F-045 est livrée (c'est la raison de la dépendance) ; sinon la liste des types admis se limite aux cinq de F-017.
  - H4 — « Depuis un modèle » est un second geste (menu de « Nouvelle ligne ») plutôt qu'un modèle par défaut qui change le comportement du bouton : F-018-AC23 reste vrai pour tous les utilisateurs existants (F-047-AC8). Notion applique un modèle par défaut : reporté.
  - H5 — Pas de limite au nombre de modèles de ligne dans le format ; un nom de modèle de ligne, comme un titre de page, est limité à 200 unités UTF-16 (F-001, F-017 H8).
  - H6 — Liste fermée provisoire des tests d'autres features à modifier, relevée le 2026-10-30 sur `origin/main` (`a64bf5f`), à figer par la conception (écart documenté, comme F-020 H12) ; seule la valeur qui figeait un nombre d'exports, une liste de codes d'erreur ou une version refusée y change :
    - F-001 (`packages/document/test/`) : `corbeille.test.ts` (`EXPORTS_ATTENDUS` l.394 : deux exports ; `CODES_ATTENDUS` l.439 : un code).
    - F-017 (`packages/document/test/`) : `table-contrat.test.ts`, `table-lecture.test.ts` (liste blanche à quatre types racine si un test l'énumère), `aides-table.ts` ; les versions refusées y sont déjà forgées à 99 par F-045 (F-045 H10) et ne sont plus retouchées.
    - F-029 (`packages/document/test/`) : `borne-contrat.test.ts` (F-029-AC15, F-017-AC25 ; `EXPORTS_DU_PAQUET` l.57 : deux exports ; union des codes l.145 : un code).
    - F-045 (`apps/web/test/vues-de-table/`) : `coutures-etiquettes.test.ts` (F-045-AC29, livré par F-045) : les fichiers nouveaux qui lisent `ValeurDeCellule` ou `.options` entrent dans sa liste fermée.
    - F-018 (`apps/web/test/`) : `vues-de-table/structure.test.ts` (aucun changement attendu : ses règles n'ont pas de liste de modules) ; les tests de création d'une ligne (F-018-AC23) doivent passer inchangés (F-047-AC8).
    - F-019 (`apps/web/test/vues-de-table/`) : aucun test attendu à modifier ; `lignes-affichees.test.tsx` et `filtres-et-tris.test.ts` doivent passer inchangés puisque la table lue ne change pas (F-047-AC12).
  - H7 — Conflits avec les branches en cours (ordre d'intégration, sans dépendance de code) : F-034 change `packages/document/src/document-table.ts` ; F-021 ajoute à `apps/web/src/vues-de-table/` ; F-038 et F-039 (tables) peuvent toucher aux mêmes fichiers (`EnTetes.tsx`, `menus.ts`, `PanneauDesOptions.tsx`, `table.classes.ts`) mais ne changent pas la version du document de table (conception de F-045). Cette feature se code après F-045, F-034 et F-021, de préférence après F-038 et F-039.
  - H8 — Conception requise avant le code (agent-architecte-conception, ADR) : amendement de l'ADR-0016 (version suivante, racine `modeles`, forme stockée) ; la branche `F-044` en porte déjà la proposition (« amendement F-044 »), à rattacher à F-047 et à ordonner après l'amendement de F-045 ; emplacement des modules de l'écran dans `apps/web/src/vues-de-table/` ; découpage en blocs (blocs 5 et 6 de la conception de F-044). Aucune nouvelle dépendance directe attendue ; agent-veille sur déclencheur seulement.
  - H9 — Ne pas reprendre le vocabulaire « template » dans l'interface : « Modèle », comme le reste de l'interface en français.
- Prérequis à la charge du dev (fichiers refusés à un agent) : aucun nouveau paquet de workspace ni dépendance directe attendus ; si H3 élève la version du document d'espace, `packages/contrats` et le garde de `apps/server` changent (fichiers partagés, à signaler) ; `.dependency-cruiser.cjs` seulement si la conception propose une règle nouvelle.
- Pourquoi ce tier : changement de format du document de table (version suivante, racine `modeles`), élargissement du contrat public de `@notionlike/document` (exports, code d'erreur `modele-introuvable`) et nouveau flux de création de ligne ; en cas de doute entre deux tiers, le plus élevé.
- Agents : agent-architecte-conception, agent-frontend (agent-veille sur déclencheur)
- Dépend de : F-045 (version du document de table, valeurs par défaut des étiquettes), F-017, F-018 (livrées) ; ordre d'intégration après F-034 et F-021 (H7)
