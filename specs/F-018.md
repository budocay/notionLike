# SPEC F-018 — Vue tableau d'une base de données

Statut : validée
Tier : structurel
Revue : reviewer-frontend

- Objectif (une phrase, côté métier) : une personne crée une table depuis la barre latérale, y ajoute des colonnes typées et des lignes, remplit ses cellules au clavier comme à la souris, sans compte ni réseau, et retrouve la même table en rouvrant l'application sur le même appareil.
- Vocabulaire :
  - « table » : une page de l'arborescence dont le type est `table` (F-017 H2) : son identifiant est celui de la page, son titre est le titre de la page, son contenu est un document de table.
  - « type d'une page » : `page` ou `table`. Il est fixé à la création et ne change jamais.
  - « base de table » : la base IndexedDB `notionlike:table:<idEspace>:<idTable>` d'un document de table (F-002-AC25).
  - « écran de table » : ce que la zone principale affiche quand la page sélectionnée est une table : son titre, le sélecteur de vues et la vue active.
  - « vue » : une présentation des lignes d'une table. Cette feature livre la vue « Tableau » ; F-020 et F-021 en ajoutent.
  - « grille » : la vue « Tableau » : une rangée d'en-têtes (une par colonne) et une rangée par ligne affichée.
  - « cellule courante » : la cellule de la grille qui porte le focus. « Mode édition » : l'état où la cellule courante présente un champ de saisie.
  - « lignes affichées » : la suite ordonnée des lignes qu'une vue présente. Dans cette feature, ce sont toutes les lignes de la table lue, dans l'ordre manuel ; F-019 la restreint et la réordonne.
  - « colonne de titre » : la première colonne de type `texte` dans l'ordre des colonnes de la table lue, s'il y en a une. Elle est calculée, jamais enregistrée.
  - « réglages de vue » : ce que l'appareil conserve pour une table, hors de tout document Yjs : la vue active et la largeur des colonnes dans cette feature (H3). Ils sont propres à l'appareil et ne sont jamais partagés.
  - « fenêtre » : les rangées de la grille réellement présentes dans le DOM à un instant donné (H9).
  - « Mod » : défini par `specs/F-006.md`. « document d'espace », « arborescence lue », « réplique », « converger », « erreur typée » : définis par `specs/F-001.md`. « module de persistance », « page sélectionnée », « rechargement » : définis par `specs/F-002.md`. « document de table », « colonne », « option », « ligne », « cellule », « table lue » : définis par `specs/F-017.md`. « supprimer définitivement », « racine de corbeille » : définis par `specs/F-007.md`.
- Critères d'acceptation :
  - Document d'espace : une page de type `table` (`packages/document`)
    - F-018-AC1 : QUAND un appelant crée une table avec un titre, à la racine ou sous une page existante, LE SYSTÈME DOIT inscrire dans le document d'espace une page de type `table`, lui donner un identifiant tiré de `crypto.randomUUID()` et jamais fourni par l'appelant (F-007-AC30 reste vrai), et la faire apparaître dans l'arborescence lue sous le parent et à la position demandés, comme F-001-AC2 le prescrit pour une page.
    - F-018-AC2 : LE SYSTÈME DOIT exposer le type de chaque page (`page` ou `table`) dans l'arborescence lue et dans la corbeille ; une entrée qui ne porte aucun type DOIT se lire `page`, règle permanente du format : un document écrit avant cette feature se lit donc comme avant.
    - F-018-AC3 (version du document d'espace) : QUAND la première page de type `table` est inscrite dans un document d'espace, LE SYSTÈME DOIT élever la version de format de ce document à 2 dans la même transaction Yjs que cette inscription ; LE SYSTÈME NE DOIT écrire aucune version à l'ouverture d'un document, ni par une opération qui n'inscrit pas de table : un document sans table DOIT rester à la version 1, prouvé par un test qui rejoue chaque opération de la façade sur un document sans table et constate la version lue et l'absence de toute écriture de version.
    - F-018-AC4 : LE SYSTÈME DOIT lire et modifier un document d'espace de version 1 comme de version 2, et refuser par `version-non-prise-en-charge`, sans rien modifier, toute version lue supérieure à 2 ; la forme stockée d'une version 2 DOIT être telle qu'une application limitée à la version 1 refuse le document entier (ADR-0002, « Lecture », étape 1 : clé `version` de `meta` présente et différente de `1`), prouvé par un test qui applique cette règle de la version 1 à l'état d'un document qui porte une table, sur la réplique qui l'a créée et sur une réplique qui a convergé avec elle.
    - F-018-AC5 (la version ne baisse jamais) : QUAND deux répliques d'un même document d'espace élèvent séparément sa version puis convergent, quel que soit l'ordre d'application des mises à jour, LE SYSTÈME DOIT lire sur les deux une version qui n'est inférieure à aucune version inscrite par l'une d'elles ; un test DOIT le prouver pour deux élévations à 2, et pour une élévation à 2 concurrente d'une version 3 inscrite directement par le test dans la forme stockée (la lecture DOIT alors être refusée sur les deux répliques).
    - F-018-AC6 : LE SYSTÈME DOIT appliquer à une page de type `table`, sans règle nouvelle, toutes les opérations que la façade du document d'espace offre pour une page (renommer, déplacer, mettre à la corbeille, restaurer, supprimer définitivement, et servir de parent) ; aucune opération NE DOIT changer le type d'une page ; les tests de convergence à graine fixe de F-001 et de F-007 DOIVENT être repris par de nouveaux tests dont les suites d'opérations comprennent des créations de table, et constater la même arborescence, la même corbeille et les mêmes types sur toutes les répliques.
    - F-018-AC7 : SI une entrée du document d'espace porte un type qui n'est ni `page` ni `table`, ALORS LE SYSTÈME DOIT l'ignorer à la lecture comme une entrée mal formée (F-001-AC16, AC17) ; SI une entrée de type `table` figure dans un document dont la version lue est 1 (pair défectueux qui écrit sans passer par le module), ALORS LE SYSTÈME DOIT la lire comme une table, de la même façon sur toutes les répliques, sans lever d'exception.
    - F-018-AC8 (couture de l'interface de `@notionlike/document`) : LE SYSTÈME DOIT ajouter l'opération de création de table et le type des pages lues, et laisser inchangés les autres exports déjà livrés (mêmes noms, mêmes signatures, mêmes codes d'erreur pour les mêmes refus ; `creerDocumentEspace` fournit toujours un document de version 1) ; les tests de listes des features livrées (F-003-AC24, F-007-AC24, F-016-AC29, F-017-AC25) DOIVENT être mis à jour de cette seule addition et passer ; un test de couture DOIT énumérer les paquets du workspace qui dépendent de `@notionlike/document` (`apps/web`, et `apps/server` si F-012 est livrée) et échouer si l'un d'eux ne passe pas sa vérification de types et ses tests.
    - F-018-AC9 (couture du format du document d'espace) : un test DOIT énumérer les modules d'`apps/web` qui lisent l'arborescence ou la corbeille (énumération de F-002-AC20 reprise), prouver pour chacun qu'un document d'espace qui porte des tables, enregistré par la persistance puis relu dans un document vierge, donne la même arborescence, la même corbeille et les mêmes types, et échouer si l'un d'eux n'est pas couvert ; un second test DOIT énumérer les modules d'`apps/web` qui tirent d'un identifiant de page un nom de base ou un nom de document (éditeur de F-003, corbeille de F-007, et synchronisation de F-013, pour celles qui sont livrées) et échouer si l'un d'eux ouvre, crée ou synchronise un document de page pour une page de type `table`, ou un document de table pour une page de type `page`.
  - Barre latérale
    - F-018-AC10 : QUAND l'utilisateur active « Nouvelle table » à la racine, ou « Ajouter une table » sur une page, LE SYSTÈME DOIT créer une table au titre vide en dernière position sous le parent visé, l'afficher dans la barre latérale avec le libellé « Sans titre », déplier son parent, la sélectionner et ouvrir la saisie de son titre, comme F-002-AC5 le prescrit pour une page.
    - F-018-AC11 : LE SYSTÈME DOIT distinguer une table d'une page dans la barre latérale et dans l'écran de la corbeille par une marque qui ne repose pas sur la couleur seule et par un nom accessible qui commence par « Table » ; les actions de F-002 sur une rangée (renommer, ajouter une sous-page, mettre à la corbeille, replier, déplier, sélectionner), et celles de F-006 si elle est livrée, DOIVENT rester offertes sur une table, inchangées, et atteignables au clavier seul (F-002-AC10).
  - Ouverture d'une table
    - F-018-AC12 : QUAND la page sélectionnée est une table, LE SYSTÈME DOIT afficher l'écran de table dans la zone principale, sous la forme d'adresse `#/page/<idTable>` de F-002, sans forme d'adresse nouvelle ; LE SYSTÈME NE DOIT créer pour elle ni éditeur, ni document de page, ni base de page, y compris quand F-003 est livrée.
    - F-018-AC13 : QUAND une table est ouverte, LE SYSTÈME DOIT ouvrir son document par `ouvrirDocumentTable` sur un `Y.Doc` rempli par le module de persistance depuis la base de table que désignent l'identifiant de l'espace ouvert et celui de la table, nom tiré de la fonction de nommage du module (F-002-AC25) ; TANT QUE la relecture n'a ni abouti ni échoué, LE SYSTÈME DOIT afficher un état de chargement à la place de la grille, sans action de modification, pendant 10 secondes au plus (F-002-AC24) ; LE SYSTÈME NE DOIT émettre aucune mise à jour Yjs du fait de l'ouverture (ni `creerDocumentTable`, ni colonne par défaut), prouvé par un test qui compare l'état encodé du document avant et après ; QUAND l'application est rechargée, LE SYSTÈME DOIT afficher la même table (mêmes colonnes, mêmes options, mêmes lignes, même ordre, mêmes cellules).
    - F-018-AC14 : SI la persistance d'une table échoue ou n'aboutit pas dans le délai, ALORS LE SYSTÈME DOIT se comporter comme F-002-AC16 et F-002-AC24 le prescrivent pour le document d'espace : table tenue en mémoire et modifiable, avertissement visible et annoncé, rien d'appliqué au document de table ni d'affiché de ce qu'une ouverture ou une tentative abandonnée à son échéance lit plus tard, et rien d'écrit de son fait dans cette base ; la bibliothèque de persistance peut finir la lecture qu'elle avait lancée avant l'échéance (F-002-AC24, F-002 H15, F-030-AC7) ; la coupure n'est pas définitive (décision du dev du 2026-10-09, `specs/F-030.md` H0) : QUAND la table est rouverte, LE SYSTÈME DOIT retenter sa base (F-030-AC3), et la reprise suit F-030 pour le document de table comme pour le document d'espace (tentatives de F-030-AC1 et AC2, fusion sans perte de l'état relu et de l'état en mémoire de F-030-AC4 à AC6, avertissement tenu puis retiré de F-030-AC12 à AC14, refus de version de F-018-AC15 appliqué avant toute écriture comme F-030-AC10) ; QUAND une table dont le document porte une modification non enregistrée (au sens de F-030) est quittée (F-018-AC16), LE SYSTÈME DOIT conserver ce document en mémoire, poursuivre ses tentatives, le libérer une fois la reprise faite, et rendre ce même document si la table est rouverte avant, comme F-003-AC18 le prescrit pour une page ; un test DOIT modifier une cellule pendant une coupure, quitter la table, y revenir et lire la modification, puis rétablir la base et la relire dans un document vierge, et la session de table DOIT entrer dans l'énumération de F-030-AC19 ; aucune erreur non interceptée ni rejet de promesse non géré dans les trois cas de F-002-AC16 et à l'échéance, la limite acceptée de F-002-AC16 (ouverture qui réussit pour le contrôle préalable du module de persistance puis échoue aussitôt pour la bibliothèque) valant ici telle quelle.
    - F-018-AC15 : SI le document relu porte une version de format non prise en charge (F-017-AC22), ou est un document d'un autre genre (F-017-AC23), ALORS LE SYSTÈME DOIT afficher dans la zone principale, à la place de la grille, un message en français sans code technique (« Cette table demande une version plus récente de l'application. » dans le premier cas, « Cette table est illisible. » dans le second), ne proposer aucune action de modification de la table, n'écrire aucune mise à jour dans sa base, et laisser la barre latérale utilisable.
    - F-018-AC16 : QUAND l'utilisateur quitte une table (autre page sélectionnée, corbeille, table mise à la corbeille), LE SYSTÈME DOIT fermer la persistance que l'écran tenait sur elle et détruire son `Y.Doc` en mémoire, après que les écritures en cours ont été remises à la persistance ; un test DOIT ouvrir puis quitter vingt tables et constater qu'aucune persistance n'est restée ouverte du fait de l'écran.
    - F-018-AC17 : QUAND une table sans colonne est affichée, LE SYSTÈME DOIT présenter, à la place de la grille, une invitation « Ajouter une colonne » ; QUAND elle a des colonnes et aucune ligne, LE SYSTÈME DOIT afficher la rangée d'en-têtes et l'action « Nouvelle ligne ».
  - Colonnes
    - F-018-AC18 : QUAND l'utilisateur ajoute une colonne, LE SYSTÈME DOIT lui demander un nom et un type parmi « Texte », « Nombre », « Case à cocher », « Date » et « Sélection » (Texte par défaut), créer la colonne en dernière position par une seule opération du document de table, et placer le focus sur son en-tête ; LE SYSTÈME NE DOIT offrir aucune commande qui change le type d'une colonne existante (F-017 H3).
    - F-018-AC19 : QUAND l'utilisateur renomme une colonne et valide (Entrée ou sortie du champ), LE SYSTÈME DOIT afficher le nouveau nom ; QUAND il annule (Échap), LE SYSTÈME DOIT conserver l'ancien ; un nom vide DOIT s'afficher « Sans nom » ; SI le nom dépasse 200 caractères, ALORS LE SYSTÈME DOIT refuser la saisie, afficher un message qui cite la limite et conserver le texte saisi.
    - F-018-AC20 : LE SYSTÈME DOIT offrir sur chaque en-tête les commandes « Déplacer à gauche » et « Déplacer à droite », qui déplacent la colonne d'une place par une seule opération du document de table, gardent le focus sur son en-tête et annoncent sa nouvelle place ; SI la colonne est déjà la première (ou la dernière), ALORS la commande DOIT être exposée comme indisponible et NE DOIT émettre aucune mise à jour Yjs.
    - F-018-AC21 : QUAND l'utilisateur demande la suppression d'une colonne, LE SYSTÈME DOIT afficher une confirmation en boîte de dialogue d'alerte qui cite le nom de la colonne, dit que ses valeurs ne seront plus accessibles et que l'action ne peut pas être annulée, focus placé sur « Annuler » ; QUAND il confirme, LE SYSTÈME DOIT supprimer la colonne par une seule opération et placer le focus sur l'en-tête voisin, ou sur l'invitation de F-018-AC17 s'il n'en reste aucun ; QUAND il annule, LE SYSTÈME NE DOIT rien modifier et DOIT rendre le focus à la commande d'origine.
    - F-018-AC22 (options d'une colonne « Sélection ») : LE SYSTÈME DOIT offrir, depuis l'en-tête d'une colonne `selection`, un panneau « Options » qui permet d'ajouter une option (libellé), de la renommer, de la monter ou la descendre d'une place, et de la retirer, chacune par une seule opération du document de table ; le retrait DOIT être précédé d'une confirmation qui dit que les cellules portant cette option deviendront vides ; un libellé vide DOIT s'afficher « Sans libellé » ; SI un libellé dépasse 100 caractères, ALORS LE SYSTÈME DOIT refuser la saisie avec un message qui cite la limite.
  - Lignes
    - F-018-AC23 : QUAND l'utilisateur active « Nouvelle ligne », LE SYSTÈME DOIT créer une ligne sans valeur en dernière position par une seule opération, l'amener dans la fenêtre et placer le focus sur sa première cellule.
    - F-018-AC24 : LE SYSTÈME DOIT offrir sur chaque ligne les commandes « Monter la ligne » et « Descendre la ligne », déclenchables aussi par Alt+Maj+Flèche haut et Alt+Maj+Flèche bas quand une cellule de la ligne est la cellule courante hors mode édition ; chacune DOIT déplacer la ligne d'une place parmi les lignes affichées par une seule opération, garder la cellule courante sur la même ligne et la même colonne, et annoncer la nouvelle place ; SI la ligne est déjà la première (ou la dernière), ALORS la commande et son raccourci DOIVENT être exposés comme indisponibles et NE DOIVENT émettre aucune mise à jour Yjs.
    - F-018-AC25 : QUAND l'utilisateur demande la suppression d'une ligne, LE SYSTÈME DOIT afficher une confirmation en boîte de dialogue d'alerte qui dit que l'action ne peut pas être annulée, focus placé sur « Annuler » ; QUAND il confirme, LE SYSTÈME DOIT supprimer la ligne par une seule opération et placer la cellule courante sur la même colonne de la ligne suivante, ou de la précédente s'il n'y en a pas.
  - Cellules
    - F-018-AC26 (affichage) : LE SYSTÈME DOIT afficher une cellule selon le type de sa colonne, par des règles fixes qui ne dépendent ni de la langue ni du fuseau de l'appareil : `texte` sur une ligne, tronqué par des points de suspension, le texte entier restant lisible par les technologies d'assistance ; `nombre` par la forme décimale la plus courte du nombre, le séparateur décimal étant la virgule, sans séparateur de milliers ; `case` par une case à cocher, non cochée pour `false` comme pour une cellule vide ; `date` sous la forme `JJ/MM/AAAA` ; `selection` par le libellé de l'option ; une cellule vide de type `texte`, `nombre`, `date` ou `selection` DOIT s'afficher sans texte. Un test DOIT prouver l'affichage sur une table de cas par type, tenue en un seul endroit, et constater que le module n'appelle ni `Intl`, ni `toLocaleString`, ni `toLocaleDateString`.
    - F-018-AC27 (texte) : QUAND l'utilisateur valide un texte dans une cellule `texte`, LE SYSTÈME DOIT l'écrire tel que saisi, sans le rogner ; un texte vidé DOIT vider la cellule ; SI le texte dépasse 2 000 caractères, ALORS LE SYSTÈME DOIT refuser la validation, afficher un message qui cite la limite, garder le mode édition et le texte saisi, et n'émettre aucune mise à jour Yjs.
    - F-018-AC28 (nombre) : QUAND l'utilisateur valide une saisie dans une cellule `nombre`, LE SYSTÈME DOIT en retirer les espaces de début et de fin, puis l'accepter si elle se compose d'un signe `-` facultatif, d'au moins un chiffre, et d'une partie décimale facultative introduite par une virgule ou un point, et écrire le nombre correspondant ; une saisie vide DOIT vider la cellule ; SI la saisie a une autre forme (lettres, exposant, espace ou séparateur de milliers, deux séparateurs) ou donne un nombre non fini, ALORS LE SYSTÈME DOIT refuser la validation, afficher « Saisissez un nombre, par exemple 12 ou 3,5. », garder le mode édition et le texte saisi, et n'émettre aucune mise à jour Yjs ; l'analyse DOIT être une fonction sans DOM, prouvée sur une table de cas (dont `0`, `-0`, `007`, `1,5`, `1.5`, `,5`, `5,`, `1 000`, `1e3`, `--1`, `Infinity`, une suite de 400 chiffres).
    - F-018-AC29 (case) : QUAND l'utilisateur presse Espace sur une cellule `case` courante, ou clique sa case, LE SYSTÈME DOIT écrire `true` si elle se lisait non cochée (`false` ou vide) et `false` sinon, sans passer par le mode édition.
    - F-018-AC30 (date) : QUAND l'utilisateur valide une date dans une cellule `date`, par un champ de date dont la valeur est lue au format `AAAA-MM-JJ` et bornée de `0001-01-01` à `9999-12-31`, LE SYSTÈME DOIT écrire cette valeur telle quelle, sans la faire passer par un objet date ni par le fuseau de l'appareil ; un champ vidé DOIT vider la cellule ; SI la valeur n'est pas une date du calendrier que le document accepte (F-017-AC18), ALORS LE SYSTÈME DOIT refuser la validation, afficher « Saisissez une date valide. » et n'émettre aucune mise à jour Yjs.
    - F-018-AC31 (sélection) : QUAND l'utilisateur ouvre une cellule `selection`, LE SYSTÈME DOIT présenter la liste des options de la colonne dans leur ordre, précédée de « Aucune », l'option courante marquée ; QUAND il en choisit une, LE SYSTÈME DOIT écrire son identifiant, ou vider la cellule pour « Aucune » ; QUAND la colonne n'a aucune option, la liste DOIT proposer « Gérer les options » (F-018-AC22).
    - F-018-AC32 : QUAND l'utilisateur valide une saisie (Entrée, Tab ou sortie du champ), LE SYSTÈME DOIT écrire la cellule par une seule opération du document de table, et n'émettre aucune mise à jour Yjs si la valeur validée est celle que la cellule portait déjà ; QUAND il presse Échap en mode édition, LE SYSTÈME DOIT quitter le mode édition sans rien écrire et garder la cellule courante.
  - Clavier et accessibilité
    - F-018-AC33 (navigation de cellule en cellule) : TANT QUE la grille a le focus hors mode édition, LE SYSTÈME DOIT déplacer la cellule courante par les flèches (une cellule dans la direction, sans sortir de la grille ni boucler), par Début et Fin (première et dernière cellule de la ligne), Mod+Début et Mod+Fin (première cellule de la première ligne, dernière cellule de la dernière ligne), Page précédente et Page suivante (d'une hauteur de fenêtre) ; Entrée ou F2 DOIT entrer en mode édition, de même que la frappe d'un caractère sur une cellule `texte` ou `nombre`, qui remplace alors son contenu ; Suppr ou Retour arrière DOIT vider la cellule courante ; en mode édition, Entrée DOIT valider et descendre d'une ligne, Tab et Maj+Tab DOIVENT valider et passer à la cellule suivante ou précédente de la ligne. Hors mode édition, Tab DOIT quitter la grille : elle ne compte que pour un seul arrêt de tabulation.
    - F-018-AC34 : LE SYSTÈME DOIT exposer la grille aux technologies d'assistance comme une grille (rôles de grille, de rangée, d'en-tête de colonne et de cellule), avec le nombre total de lignes affichées et de colonnes et l'indice de chaque rangée présente, de sorte que la fenêtre de F-018-AC46 ne fausse pas ces nombres ; chaque commande d'en-tête, de ligne et de cellule DOIT être atteignable et déclenchable au clavier seul et porter un nom accessible en français qui cite le nom de la colonne ou la place de la ligne ; aucun déplacement, aucun réglage de largeur NE DOIT avoir le pointeur pour seule voie.
  - Mises à jour reçues, erreurs et limites
    - F-018-AC35 : QUAND la table lue change sans action dans l'écran (mise à jour Yjs appliquée au document de table), LE SYSTÈME DOIT mettre la grille à jour sans rechargement et garder la cellule courante sur la même ligne et la même colonne, désignées par leurs identifiants ; SI la ligne ou la colonne de la cellule courante a disparu, ALORS LE SYSTÈME DOIT placer la cellule courante sur la cellule voisine la plus proche, ou sur l'invitation de F-018-AC17.
    - F-018-AC36 : SI la ligne ou la colonne d'une cellule en mode édition disparaît de la table lue, ALORS LE SYSTÈME DOIT quitter le mode édition sans rien écrire et afficher « La cellule que vous modifiiez a été supprimée. » ; SI la valeur d'une cellule en mode édition change par une mise à jour reçue, ALORS LE SYSTÈME DOIT garder le texte en cours de saisie, et la validation DOIT l'écrire (dernière écriture gagne, F-017 H6).
    - F-018-AC37 : SI une opération est refusée par une erreur typée du document de table (identifiant absent ou supprimé après une mise à jour reçue, valeur non conforme, position invalide), ALORS LE SYSTÈME DOIT afficher un message en français sans code technique, laisser la grille conforme à la table lue et rester utilisable ; le module qui traduit les codes d'erreur en messages DOIT donner un message pour chaque code que `@notionlike/document` publie, prouvé par un test qui énumère la liste publiée.
    - F-018-AC38 : SI un nom de colonne, un libellé d'option ou un texte de cellule contient du balisage HTML ou un script, ALORS LE SYSTÈME DOIT l'afficher comme du texte, sans l'interpréter, dans la grille, dans les listes, dans les noms accessibles et dans les confirmations.
    - F-018-AC39 : LE SYSTÈME NE DOIT émettre aucune requête réseau du fait de cette feature, et toutes les actions de l'écran de table DOIVENT fonctionner réseau coupé (F-002-AC19 reste vrai).
  - Réglages de vue (propres à l'appareil)

SI F-010 est livrée, ALORS cette feature DOIT étendre la liste fermée du test de F-010-AC19 de ce qu'elle fait écrire dans le stockage du navigateur (le motif de clé `notionlike:vue:<idEspace>:<idTable>` de `localStorage` et le motif de nom des bases de table), et un test DOIT constater qu'un enregistrement de réglages de vue ne contient ni nom, ni courriel, ni identifiant de compte, ni jeton.

- Hypothèses tranchées par agent-planif en l'absence du dev, que la validation de cette spec entérine :
  - H1 — Une table est une page de type `table` du document d'espace (cible posée par F-017 H2), et ce type est un changement de format : version 2 du document d'espace. L'ADR-0002 tolère et ignore un champ inconnu : sans version, une application plus ancienne lirait une table comme une page, l'ouvrirait dans l'éditeur et créerait un document de page à son nom. Avec la version 2, elle refuse l'espace entier et demande une mise à jour (F-002-AC17). La règle suit celle du document de page (F-003 H4) : la version n'est écrite que lorsqu'une table est inscrite, jamais à l'ouverture, si bien qu'un espace sans table reste lisible par une application ancienne ; et le numéro introduit est la version prise en charge par `main` au premier commit de code, plus un (2 si aucune autre feature n'a étendu ce format d'ici là). La forme stockée de la version (F-018-AC4, AC5) est fixée par l'amendement de l'ADR-0002, sous deux contraintes : une application de version 1 refuse, et la version lue ne baisse jamais. Difficile à défaire : c'est le format, et dès qu'une table existe dans un espace, les applications antérieures à cette feature ne l'ouvrent plus.
  - H2 — Aucune règle d'arborescence nouvelle : une table se renomme, se déplace, va à la corbeille et peut porter des sous-pages comme toute page (F-018-AC6, AC11). Interdire les sous-pages d'une table demanderait une règle de lecture de plus, que deux déplacements simultanés pourraient de toute façon violer. Le type est écrit une fois, à la création : aucune opération ne le change, ce qui écarte la conversion d'une page en table. `page:<e>:<x>` et `table:<e>:<x>` restent deux documents distincts (F-012 H2) ; pour une table, seul le second est ouvert (F-018-AC12, AC9).
  - H3 — Où vit la configuration d'une vue : sur l'appareil, pas dans le document de table. Trois raisons. (a) Un `lecteur` doit pouvoir élargir une colonne, filtrer, trier et changer de vue sans écrire dans un document (F-013-AC25) : une configuration partagée le lui interdirait. (b) Une configuration dans le document serait un changement de format du document de table à chaque feature de vue (versions 2, 3, 4), avec pour chacune le refus de la table par les applications plus anciennes. (c) Ce choix se défait dans le bon sens : ajouter plus tard des vues partagées reste possible par une version nouvelle du document de table, les réglages locaux servant de valeur initiale ; l'inverse demanderait de retirer du contenu d'un format publié. Ce qui reste partagé, parce que c'est le contenu : l'ordre des colonnes, l'ordre des options et l'ordre manuel des lignes (F-017 H9). Conséquences, écrites dans les specs concernées : la définition des filtres et des tris (F-019), la colonne de regroupement du kanban (F-020) et la colonne de date du calendrier (F-021) vivent dans des sections des mêmes réglages de vue ; deux membres ne voient pas la même vue d'une table, et un même compte ne retrouve pas ses réglages sur un autre appareil ; l'ordre des cartes d'un kanban n'a pas de rang propre et suit l'ordre manuel des lignes (F-020). Support : `localStorage`, parce que la lecture y est immédiate (aucun état de chargement de plus avant le premier affichage) et que les valeurs sont petites ; un seul module y touche (F-018-AC40). Rien n'y est écrit tant qu'un réglage n'est pas changé ; dès qu'un réglage l'est, la clé existe, et le contrôle de F-010 qui énumère le stockage du navigateur ne reste vrai que parce que cette feature étend sa liste fermée (F-018-AC40, règle de F-010-AC19 : chaque feature qui écrit dans le stockage ajoute son entrée, rien du compte, aucun jeton). Limite acceptée : sur un appareil partagé, les réglages d'une personne servent à la suivante (même limite que F-013 H3). Se défait sans coût pour les données : les réglages sont un confort, jamais un contenu.
  - H4 — Le format des réglages de vue s'étend par sections, et l'extension est prévue dès cette feature : une section inconnue est conservée à la réécriture, une section mal formée est lue à ses valeurs par défaut, une version inconnue n'est jamais réécrite (F-018-AC41). Deux onglets d'un même appareil peuvent tourner sous deux versions de l'application (F-023) : sans cette règle, l'onglet ancien effacerait les sections du plus récent.
  - H5 — Aucune écriture à l'ouverture d'une table, et aucune colonne par défaut (F-018-AC13, AC17). Deux appareils qui ouvrent la même table vide n'écrivent rien et ne peuvent donc pas créer chacun leur colonne initiale. `creerDocumentTable` n'est pas appelé par `apps/web` : le document naît vide, par `ouvrirDocumentTable` (F-017-AC23).
  - H6 — Suppression d'une colonne, d'une ligne ou d'une option : confirmation à chaque fois (F-018-AC21, AC22, AC25). Le document garde l'élément sous drapeau (F-017 H5), mais aucune feature n'en offre la restauration, et la grille n'a pas d'annulation : pour l'utilisateur, l'action est irréversible. La confirmation des lignes se lève sans coût le jour où une annulation existe.
  - H7 — Saisie et affichage par des règles fixes, en français, indépendantes de l'appareil (F-018-AC26, AC28, AC30) : deux membres lisent le même texte pour la même valeur, et les tests ne dépendent pas de la langue de la machine qui les lance. Le nombre s'affiche avec une virgule et se saisit avec une virgule ou un point ; les très grands et très petits nombres s'affichent sous la forme à exposant que le langage produit, et l'exposant n'est pas accepté en saisie : limite acceptée. La date se saisit par le champ de date du navigateur, dont l'apparence suit la langue du navigateur, mais dont la valeur est toujours `AAAA-MM-JJ` ; elle n'est jamais convertie par un objet date (F-017 H4). À confirmer par la veille : le comportement de ce champ sous jsdom avec Testing Library (frappe, valeur invalide, bornes), que `MEMORY/VEILLE.md` ne couvre pas.
  - H8 — Bibliothèque de table : TanStack Table, que la fiche du projet nomme, retenue sous réserve de la veille et confinée au module des vues de table (F-018-AC54). `MEMORY/VEILLE.md` ne la couvre pas : nom exact du paquet pour React, version, licence, date de publication, dépendances de pair (React 19), comportement sous jsdom et en mode strict, CVE sont à confirmer par la veille, sans quoi rien n'est installé. Elle ne porte que le modèle de colonnes et de rangées de la grille : la fenêtre (F-018-AC46), l'analyse des saisies, les lignes affichées (F-018-AC45) et, plus tard, les filtres et les tris (F-019) sont des fonctions du projet, prouvées sans elle. Repli décidé d'avance : si la veille établit que la version 9 de la fiche n'est pas publiée comme version stable, qu'elle n'admet pas React 19, ou qu'elle ne tourne pas sous jsdom sans toucher à la configuration de test, la grille est écrite sans bibliothèque ; aucun critère de cette spec ne change, et la dépendance disparaît des prérequis.
  - H9 — Grandes tables : ce qui est garanti et ce qui ne l'est pas. Cible : 5 000 lignes et 30 colonnes (F-017 H8 : « quelques milliers de lignes »). Garanti : le nombre de rangées dans le DOM est borné par la fenêtre, quel que soit le nombre de lignes (F-018-AC46), et la navigation au clavier atteint toute ligne (F-018-AC47). La fenêtre est écrite par le projet, sur des rangées de hauteur fixe : une division suffit, elle se prouve sans mise en page, et aucune bibliothèque de défilement virtuel n'entre (ce serait une dépendance directe que ni la fiche ni la veille ne portent). Prix : le texte d'une cellule ne revient pas à la ligne. Non garanti : aucun temps chiffré (affichage, frappe, défilement) ; le coût du calcul de la table lue à chaque transaction relève de F-017, qui n'en fixe pas ; les colonnes ne sont pas fenêtrées, une table de plusieurs centaines de colonnes sera lente ; jsdom n'a pas de mise en page, le test de F-018-AC46 prouve le compte des rangées, pas la fluidité. La mesure dans un navigateur réel est à faire par le dev sur une table de 5 000 lignes avant de valider la cible.
  - H10 — Déplacements par commandes, sans glisser-déposer (F-018-AC20, AC24) : cette feature ne dépend pas de F-006, et une commande vaut pour le pointeur comme pour le clavier. Alt+Maj+Flèche haut et bas reprennent la convention de F-006 H5 ; hors mode édition, la cellule courante n'est pas une zone de texte, il n'y a donc pas le conflit de macOS décrit là. Le seul geste au pointeur de la feature est le réglage d'une largeur, qui a son équivalent au clavier (F-018-AC43).
  - H11 — Dépendance à F-007, ajoutée à celles que la ROADMAP proposait. La suppression définitive d'une table passe par l'opération et l'écran de F-007 ; dépendre d'elle évite d'écrire deux comportements selon l'ordre de livraison, et F-007 ne dépend que de F-002. Pour chaque identifiant retiré, la base de page et la base de table sont effacées toutes les deux (F-018-AC49) : le type d'une entrée retirée n'est plus lisible après coup, et un pair défectueux peut avoir fait ouvrir l'une ou l'autre. Ce que cela ne fait pas : effacer le document du serveur (F-025).
  - H12 — Indépendance à l'ordre de livraison avec F-013, par la règle de F-011 H14 : la feature fusionnée en second porte le branchement. (a) F-013 est fusionnée la première, ce qui est l'ordre de la ROADMAP : cette feature porte F-018-AC51 à AC53, dans `apps/web` seulement (le type `table` existe déjà dans le contrat de F-012, et le serveur n'interprète aucun contenu). (b) F-018 est fusionnée la première : F-018-AC51 à AC53 sont sans objet, cette feature n'écrit rien dans le module de synchronisation, qui n'existe pas, et c'est F-013 qui, à sa livraison, synchronise les documents de table et applique la lecture seule à l'écran de table ; sa spec le prévoit par un critère conditionnel (F-013-AC46, F-013 H17, retouche du 2026-10-08), qui reprend F-018-AC51 à AC53 sans en changer le sens, et F-013-AC16 dit que la feature fusionnée en second porte le branchement. Dans les deux cas, F-018-AC9 (aucun document de page pour une table) est tenu par cette feature. Les lignes d'en-tête sont écrites pour le cas (a).
  - H13 — Deux onglets ouverts sur la même table partagent sa base et ne se voient qu'au rechargement, tant que F-013 n'est pas livrée (F-002 H7) ; rien n'est perdu, Yjs fusionne à la relecture. Le ramasse-miettes de Yjs reste actif sur le `Y.Doc` d'une table (réglage par défaut, ADR-0001) : aucune fonction ne demande le contraire.
  - H14 — Preuves sous Vitest pour tout sauf F-018-AC56 : le format et la convergence dans `packages/document`, sous Node ; l'écran, la grille, le clavier, les réglages de vue (`localStorage` de jsdom), la persistance simulée et les coutures dans `apps/web`. Les bouchons de mise en page de la fenêtre vivent dans les fichiers de test, pas dans la configuration de test (F-006 H11). Ce que jsdom ne prouve pas : le glissement d'un séparateur de largeur au pointeur, le défilement réel, le rendu du champ de date. F-018-AC56 est lancé à la main tant que la dette D-003 proposée n'est pas levée.
  - H15 — Cette spec couvre quatre lots, que la conception planifie en blocs séparés et où la feature se coupe si elle ne tient pas en une session, sans réécrire de critère : le format (F-018-AC1 à AC9), l'ouverture, la persistance et la corbeille (AC10 à AC17, AC48 à AC50), la grille et les réglages de vue (AC18 à AC47, AC54, AC55), la synchronisation (AC51 à AC53).
