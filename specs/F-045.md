# SPEC F-045 — Étiquettes : colonne « Étiquettes » (sélection multiple), options colorées, création à la frappe, filtre « contient »

Statut : validée
Tier : structurel
Revue : reviewer-frontend

- Objectif (une phrase, côté métier) : une équipe classe les lignes d'une table avec plusieurs étiquettes colorées à la fois (comme la propriété « Multi-select » de Notion), crée une étiquette en la tapant dans la cellule, et ne garde à l'écran que les lignes qui portent (ou ne portent pas) une étiquette donnée.
- Origine : retour du dev sur la RC1 (2026-10-30, donnée) : « on ne peut pas créer de template, de labels etc etc je t'avais pourtant dit de t'inspirer de Notion ». Aucune spec ne couvrait les étiquettes ; F-017 excluait explicitement « sélection multiple » et « couleur d'une option » de son périmètre. Cette feature est la moitié « étiquettes » du lot ; les modèles sont dans `specs/F-044.md` (pages) et `specs/F-047.md` (lignes de table).
- Vocabulaire :
  - « colonne `etiquettes` » : sixième type de colonne (« Étiquettes » dans l'interface), fixé à la création comme les autres (F-017 H3). Elle a des options comme une colonne `selection` (F-017, F-018-AC22).
  - « cellule d'étiquettes » : l'ensemble, sans doublon, des options de la colonne que porte une ligne. Vide = aucune étiquette ; elle se lit `null` (F-017 H12), jamais un ensemble vide.
  - « couleur d'option » : l'une des dix couleurs de la palette fermée (H4) portée par une option d'une colonne `selection` ou `etiquettes`. Une option sans couleur se lit « defaut ».
  - « création à la frappe » : créer une option depuis le champ de saisie de la cellule, sans passer par le panneau « Options ».
  - « table lue », « colonne », « option », « cellule », « façade de table », « document de table » : définis par `specs/F-017.md` ; « écran de table », « grille », « panneau Options », « boîte » : `specs/F-018.md` ; « filtre », « élément inactif » : `specs/F-019.md` ; « colonne de regroupement » : `specs/F-020.md`.
- Critères d'acceptation :
  - Modèle de document (`packages/document`)
    - F-045-AC1 : QUAND un appelant crée une colonne de type `etiquettes`, LE SYSTÈME DOIT l'exposer dans la table lue avec ce type, sans option, et toutes ses cellules vides.
    - F-045-AC2 : QUAND un appelant écrit dans une cellule d'une colonne `etiquettes` une liste d'identifiants d'options de la colonne, ou la vide, LE SYSTÈME DOIT exposer l'ensemble correspondant, rangé dans l'ordre des options de la colonne (et non dans l'ordre de saisie), sans changer aucune autre cellule ; une liste vide DOIT se lire `null`.
    - F-045-AC3 : QUAND un appelant ajoute ou retire une seule étiquette d'une cellule, LE SYSTÈME DOIT laisser les autres étiquettes de la cellule intactes ; ajouter une étiquette déjà portée, ou retirer une étiquette absente, DOIT être sans effet et n'émettre aucune mise à jour Yjs.
    - F-045-AC4 : QUAND un appelant crée une option dans une colonne `selection` ou `etiquettes` en demandant son affectation à une cellule, LE SYSTÈME DOIT créer l'option et l'affecter dans une seule transaction Yjs (une seule notification à chaque abonné, F-017-AC9) ; SI l'affectation est refusée, ALORS aucune option NE DOIT avoir été créée.
    - F-045-AC5 : QUAND un appelant donne une couleur à une option d'une colonne `selection` ou `etiquettes`, LE SYSTÈME DOIT exposer cette couleur sur l'option, sans changer son libellé, sa position ni les cellules qui la portent ; une option créée sans couleur DOIT se lire « defaut ».
    - F-045-AC6 : QUAND un appelant retire une option d'une colonne `etiquettes`, LE SYSTÈME DOIT la retirer de la liste d'options et de toutes les cellules qui la portent, sans toucher aux autres étiquettes de ces cellules (extension de F-017-AC8).
    - F-045-AC7 : QUAND deux répliques ajoutent chacune une étiquette différente à la même cellule puis convergent, LE SYSTÈME DOIT conserver les deux étiquettes sur les deux répliques ; QUAND l'une ajoute et l'autre retire la même étiquette, LE SYSTÈME DOIT lire le même résultat sur les deux répliques ; QUAND l'une retire une option pendant que l'autre l'ajoute à une cellule, LE SYSTÈME DOIT lire l'option absente et la cellule sans elle sur les deux (F-017-AC15 étendu). Le test JOUE ces trois cas dans les deux ordres d'échange.
    - F-045-AC8 : QUAND l'état complet d'un document de table qui porte une colonne `etiquettes` et des couleurs d'option est encodé en une mise à jour Yjs (format V1) puis appliqué à un document vierge, LE SYSTÈME DOIT lire la même table (F-017-AC16 étendu).
    - F-045-AC9 : SI une écriture de cellule `etiquettes` est refusée (identifiant qui n'est pas une option de la colonne ; doublon dans la liste ; plus de 100 étiquettes ; valeur qui n'est pas une liste de chaînes ; colonne d'un autre type, ou liste donnée à une colonne d'un autre type), ou si une couleur n'est pas l'une des dix de la palette, ou si l'option ou la colonne visée est absente ou supprimée, ALORS LE SYSTÈME DOIT refuser par une erreur typée et n'émettre aucune mise à jour Yjs.
    - F-045-AC10 : SI le document contient une cellule d'étiquettes mal formée, une étiquette qui désigne une option absente ou retirée, ou une couleur inconnue, ALORS LE SYSTÈME DOIT ignorer l'étiquette (ou lire la couleur « defaut ») sans lever d'exception, de la même façon sur toutes les répliques, et exposer le reste de la table ; une cellule dont aucune étiquette n'est valide DOIT se lire `null`.
    - F-045-AC11 (format) : QUAND la première colonne `etiquettes` est créée dans un document de table, LE SYSTÈME DOIT élever dans la même transaction la version de format du document à 2 sous une forme stockée telle qu'une application limitée à la version 1 refuse le document entier, au lieu d'ignorer la colonne en silence (F-017-AC20) ; LE SYSTÈME DOIT lire et écrire un document de version 1 comme avant, sans l'élever tant qu'aucune colonne `etiquettes` n'y est créée, et refuser par `version-non-prise-en-charge` toute version lue supérieure à 2 (F-017-AC22 déplacé).
  - Écran de table (`apps/web`)
    - F-045-AC12 : QUAND l'utilisateur ajoute une colonne, LE SYSTÈME DOIT proposer le type « Étiquettes » après « Sélection » (six types ; « Texte » reste le défaut), et LE SYSTÈME NE DOIT offrir aucune commande qui convertisse une colonne `selection` en `etiquettes` ou l'inverse (F-017 H3).
    - F-045-AC13 (affichage) : LE SYSTÈME DOIT afficher une cellule d'étiquettes comme des pastilles, une par étiquette, dans l'ordre des options, de la couleur de leur option, chacune portant son libellé en texte ; la cellule DOIT tenir sur une ligne, les pastilles qui ne tiennent pas étant remplacées par « +n » ; le nom accessible de la cellule DOIT énumérer tous les libellés, y compris ceux qui ne tiennent pas. La couleur ne DOIT jamais être le seul porteur de l'information. Une option de colonne `selection` DOIT s'afficher de la même façon (pastille colorée).
    - F-045-AC14 (édition) : QUAND l'utilisateur ouvre une cellule d'étiquettes (Entrée, F2 ou clic, comme F-018-AC31), LE SYSTÈME DOIT présenter un champ de saisie surmontant la liste des options de la colonne, chacune avec son état coché ou non ; QUAND il en active une (clic, Entrée ou Espace), LE SYSTÈME DOIT l'ajouter ou la retirer de la cellule par une seule opération et laisser la liste ouverte, le focus dans le champ ; Échap DOIT fermer la liste et rendre le focus à la cellule (F-018-AC21).
    - F-045-AC15 (filtrage de la liste) : QUAND l'utilisateur saisit du texte dans le champ, LE SYSTÈME DOIT ne garder dans la liste que les options dont le libellé contient ce texte, sans tenir compte de la casse ni des accents, et annoncer le nombre d'options restantes (région `status`).
    - F-045-AC16 (création à la frappe) : TANT QUE le texte saisi, une fois les espaces de tête et de queue retirés, n'est vide et ne correspond (casse et accents ignorés) à aucun libellé d'option de la colonne, LE SYSTÈME DOIT proposer, en dernière entrée de la liste, « Créer « <texte> » » ; QUAND l'utilisateur l'active, LE SYSTÈME DOIT créer l'option (libellé = texte nettoyé, couleur choisie selon H5) et l'affecter à la cellule par une seule opération (F-045-AC4), vider le champ et garder la liste ouverte. La même commande DOIT être offerte dans une cellule de colonne `selection` (l'option créée y devient la valeur de la cellule), sans changer le reste de F-018-AC31.
    - F-045-AC17 : QUAND le texte saisi correspond à un libellé existant (casse et accents ignorés), LE SYSTÈME DOIT ne pas proposer « Créer » et faire de l'option existante la cible d'Entrée ; deux appareils qui ont chacun créé hors ligne une option du même libellé DOIVENT en garder deux après convergence (pas de fusion automatique, H6), distinguées dans le panneau « Options » par leur couleur et leur rang.
    - F-045-AC18 : SI le texte saisi dépasse 100 caractères, ALORS LE SYSTÈME DOIT ne pas proposer « Créer », annoncer « Le libellé est limité à 100 caractères » et ne rien écrire ; un texte fait seulement d'espaces NE DOIT PAS ouvrir la création.
    - F-045-AC19 (clavier) : QUAND une cellule d'étiquettes a le focus dans la grille et que l'utilisateur appuie sur Suppr ou Retour arrière, LE SYSTÈME DOIT la vider (comme F-018 le fait des autres types) ; la navigation au clavier de la grille (F-018-AC27 à AC29) DOIT rester inchangée.
    - F-045-AC20 (couleur d'option) : QUAND l'utilisateur ouvre le panneau « Options » d'une colonne `selection` ou `etiquettes`, LE SYSTÈME DOIT offrir, pour chaque option, la commande « Couleur » qui présente les dix couleurs de la palette, nommées en toutes lettres, avec la couleur courante marquée ; la choisir DOIT écrire la couleur par une seule opération et mettre à jour toutes les pastilles de cette option, grille et listes ouvertes comprises.
    - F-045-AC21 (retrait d'option) : QUAND l'utilisateur retire une option d'une colonne `etiquettes`, LE SYSTÈME DOIT demander la confirmation de F-018-AC22 en indiquant que les étiquettes correspondantes disparaîtront des cellules qui la portent.
    - F-045-AC22 (palette) : LE SYSTÈME DOIT définir chacune des dix couleurs par un couple de jetons (fond et texte) du thème sombre de F-004, avec un rapport de contraste d'au moins 4,5:1 entre le texte et le fond de chaque couple, mesuré par un test ; le nom de la couleur DOIT faire partie du nom accessible de la commande qui la choisit.
    - F-045-AC23 (lecture seule) : SI F-013 est livrée, ALORS, TANT QUE l'espace est ouvert en lecture seule (F-013-AC25), LE SYSTÈME DOIT désactiver, avec la raison « Lecture seule », l'édition d'une cellule d'étiquettes, la création à la frappe et le choix de couleur ; la cellule DOIT rester lisible et annoncée.
  - Filtres, tris et autres vues
    - F-045-AC24 (filtre) : QUAND l'utilisateur ajoute un filtre sur une colonne `etiquettes`, LE SYSTÈME DOIT proposer les opérateurs « contient », « ne contient pas », « est vide » et « n'est pas vide » ; « contient » et « ne contient pas » demandent une option de la colonne ; une ligne satisfait « contient » si sa cellule porte cette option, et « ne contient pas » si elle ne la porte pas (une cellule vide satisfait donc « ne contient pas »).
    - F-045-AC25 : SI l'option d'un filtre « contient » ou « ne contient pas » est retirée, ALORS LE SYSTÈME DOIT traiter ce filtre comme un élément inactif (F-019), sans l'effacer, comme pour une colonne `selection`.
    - F-045-AC26 (pas de tri) : LE SYSTÈME NE DOIT PAS proposer une colonne `etiquettes` dans la barre des tris ; un tri enregistré sur une telle colonne DOIT être un élément inactif. (Raison : H7.)
    - F-045-AC27 (kanban) : LE SYSTÈME NE DOIT PAS proposer une colonne `etiquettes` comme colonne de regroupement du kanban ; QUAND la table n'a qu'une colonne `etiquettes` et aucune colonne `selection`, LE SYSTÈME DOIT afficher le message de F-020-AC5 inchangé. (Raison : H8.)
    - F-045-AC28 (calendrier) : SI F-021 est livrée, ALORS la vue calendrier DOIT se comporter comme avant sur une table qui porte une colonne `etiquettes` : la colonne n'est ni colonne de date, ni titre de carte.
  - Coutures et structure
    - F-045-AC29 (couture des appelants) : QUAND un type de colonne ou une valeur de cellule change de définition, un test de couture DOIT énumérer, depuis les sources, chaque appelant dans `apps/web/src` (toute source qui importe `ValeurDeCellule`, `TypeDeColonne`, `ColonneLue`, `OptionLue`, ou qui lit `.type` d'une colonne ou `.options`) et échouer si l'un d'eux ne traite pas la sixième sorte (affichage, saisie, validation, filtre, tri, regroupement, largeur, texte d'annonce), de sorte qu'aucune branche `switch` ne retombe en silence sur le cas par défaut.
    - F-045-AC30 (liste fermée des tests existants) : LE SYSTÈME DOIT laisser passer sans modification tous les tests des features livrées, SAUF ceux de la liste de H10, dont seule la valeur qui figeait « cinq types », la liste des exports, la liste des codes d'erreur ou la version refusée peut changer ; un test DOIT comparer la liste des exports du paquet `@notionlike/document` et celle de ses codes d'erreur aux listes attendues (F-017-AC25), et `pnpm contrats` DOIT finir sans violation.
    - F-045-AC31 (bout en bout) : QUAND la commande de test de bout en bout est lancée, LE SYSTÈME DOIT dérouler dans un navigateur réel le scénario : dans une table de trois lignes, ajouter une colonne « Étiquettes », créer à la frappe les étiquettes « Urgent » et « Client », en affecter deux à une ligne et une à une autre, changer la couleur de « Urgent », filtrer « contient Urgent » et constater les lignes restantes, recharger la page et retrouver les étiquettes, leurs couleurs et le filtre.
- Hors périmètre (explicitement) :
  - Étiquettes de pages (« tags » posés sur les pages de l'arborescence, filtre de pages par étiquette) : autre notion, voir H1.
  - Regroupement du kanban par une colonne `etiquettes` (une carte dans plusieurs piles) ; couleur d'une pile ; tri par étiquettes (H7, H8).
  - Conversion de type d'une colonne ; fusion de deux options (ou de doublons) ; fusion automatique des options de même libellé créées par deux appareils (H6).
  - Filtre « contient l'une de » / « contient toutes » à plusieurs options en un seul filtre : un filtre vise une option, on en empile plusieurs (H9).
  - Couleurs personnalisées (sélecteur libre, hexadécimal), thème clair, ordre des étiquettes propre à la cellule, glisser-déposer des étiquettes dans la cellule.
  - Import et export (CSV) des étiquettes ; propriétés « Personne », « Relation », « Formule ».
  - Modèles de ligne ou de page (F-044, F-047) ; commentaires sur une ligne.
- Hypothèses proposées, que la validation de cette spec entérine (le dev tranche) :
  - H1 — À trancher : « étiquettes » = une colonne de table `etiquettes` (sélection multiple), la propriété Notion « Multi-select », et non des étiquettes posées sur les pages. Recommandé : la colonne, parce qu'elle s'appuie sur le modèle de table livré (F-017 à F-020), parce que filtres et vues s'y branchent déjà, et parce qu'elle est ce que le retour du dev désigne par « labels » dans une base de données Notion. Des étiquettes de pages exigeraient un champ de plus par entrée du document d'espace, un écran de filtre de l'arborescence et la gestion du vocabulaire d'étiquettes de l'espace entier : feature à part, si le dev la veut.
  - H2 — À confirmer : ce changement est un changement de format du document de table (nouveau type de colonne, couleur d'option, cellule d'ensemble) et donc une version 2 refusée par les applications de version 1 (F-045-AC11), sur le modèle de l'élévation du document d'espace par F-018. Sans cela, une application de version 1 ignorerait la colonne (F-017-AC20) et la présenterait vide à un membre qui pourrait alors recréer la colonne. Difficile à défaire. Le serveur ne contrôle aujourd'hui que la version du document d'espace (F-018-AC57, AC58) ; la conception DOIT dire si un document de table doit aussi être gardé côté serveur ; si oui, la spec est retouchée (lignes Revue et Agents : `reviewer-backend`, `reviewer-api`, `agent-backend`), donc à revalider.
  - H3 — La cellule d'étiquettes est un ensemble à fusion par étiquette (F-045-AC7), et non une valeur « dernière écriture gagne » comme les autres cellules (F-017 H6) : deux membres qui étiquettent la même ligne hors ligne ne doivent pas s'effacer l'un l'autre. Conséquence : le format de cellule change (une structure imbriquée par cellule non vide) et la valeur lue n'est plus un scalaire (`ValeurDeCellule` s'élargit à une liste de chaînes en lecture seule). La forme stockée exacte est du ressort de la conception.
  - H4 — Palette fermée de dix couleurs, identifiants stockés : `defaut`, `gris`, `marron`, `orange`, `jaune`, `vert`, `bleu`, `violet`, `rose`, `rouge` (ceux de Notion, en français dans l'interface : « Par défaut », « Gris », etc.). Une liste fermée dans le format, parce qu'une couleur libre se retirerait mal et devrait passer une validation de contraste.
  - H5 — La couleur d'une option créée à la frappe suit la palette dans l'ordre, hors « defaut » : l'option de rang `n` prend la couleur de rang `n` modulo 9 ; elle est modifiable ensuite. Déterministe, sans hasard, donc testable.
  - H6 — Deux appareils qui créent hors ligne une option du même libellé en gardent deux après convergence : fusionner par libellé supposerait de réécrire des cellules d'une autre réplique et de choisir un gagnant. L'utilisateur renomme ou retire l'une d'elles. Compromis assumé (Notion garde un identifiant unique par vocabulaire et ne le rencontre pas hors ligne).
  - H7 — Pas de tri sur une colonne d'étiquettes : l'ordre « naturel » d'un ensemble n'existe pas (par première étiquette ? par nombre ?) et chaque réponse serait discutable. À reprendre si le dev nomme une règle.
  - H8 — Pas de regroupement du kanban par étiquettes : une carte appartiendrait à plusieurs piles, et « déplacer une carte d'une pile à l'autre » (F-020) n'aurait plus de sens univoque (retirer de laquelle ? ajouter à laquelle ?). Hypothèse alternative du dev : le permettre, une carte apparaissant dans chaque pile de ses étiquettes ; ce serait une retouche de F-020 (spec validée, donc revalidation) et une feature à part.
  - H9 — Un filtre « contient » vise une seule option ; pour « l'une de » ou « toutes », l'utilisateur empile des filtres (F-019 combine les filtres par ET, à relire dans F-019 avant la conception). Notion propose plusieurs options par filtre : à décider ultérieurement.
  - H10 — Liste fermée provisoire des tests d'autres features à modifier, relevée le 2026-10-30 sur `origin/main` (`a64bf5f`), à figer par la conception (écart documenté, comme F-020 H12) ; seule la valeur qui figeait « cinq types », les exports, les codes ou la version refusée y change, dans chaque cas :
    - F-017 (`packages/document/test/`) : `aides-table.ts` (l.166, liste `TYPES` des opérations tirées), `table-lecture.test.ts` (l.506, liste des types ; l.599, versions refusées F-017-AC22 ; l.633 et l.704, `versionInscrite(…, 2)`), `table-operations.test.ts` (l.121, `it.each` des cinq types), `table-contrat.test.ts` (listes des codes d'erreur, F-017-AC25 ; l.147, version forgée 2), `corbeille.test.ts` (`EXPORTS_ATTENDUS`, l.394, et `CODES_ATTENDUS`, l.439, si un export ou un code est ajouté).
    - F-018 (`apps/web/test/`) : `vues-de-table/colonnes.test.tsx` (l.51, les cinq types proposés par F-018-AC18), `vues-de-table/cellules.test.tsx` (cellule `selection`, F-018-AC31, pour l'ajout de « Créer » à la frappe), `vues-de-table/structure.test.ts` (liste des modules de `vues-de-table/`), `aides-table.ts`, `table-session.test.ts` (F-018-AC15 ; l.259 et l.290, version forgée 2), `table-ecran.test.tsx` (l.210, version forgée 2).
    - F-004 (`apps/web/test/`) : `jetons.test.ts` (F-004-AC7 ; l.171, le compte `12 * 7` devient `21 * 7` avec les neuf jetons de texte d'étiquette).
    - Règle commune : toute version refusée est forgée à 99 (et non 3), pour que F-047 (version 3) n'ait pas à retoucher ces tests.
    - F-021 (calendrier), si elle est fusionnée avant : les tests qui énumèrent les appelants de la définition (`calendrier-appelants.test.tsx`, `coutures-definition.test.tsx`) sont relevés au premier bloc d'écran et ajoutés à cette liste par la conception, seule la valeur qui figeait « cinq types » y changeant.
    - F-019 (`apps/web/test/vues-de-table/`) : `filtres-et-tris.test.ts`, `barres-filtres-tris.test.tsx`, `fonctions.test.ts` (opérateurs par type, `OPERATEURS_PAR_TYPE`), `lignes-affichees.test.tsx`.

  - H11 — Conflits avec les branches en cours (ordre d'intégration, sans dépendance de code) : F-034 (création de lignes linéaire) change `packages/document/src/document-table.ts` ; F-021 (calendrier) ajoute à `apps/web/src/vues-de-table/` ; F-038 et F-039 (tables, specs en cours d'écriture) peuvent toucher aux mêmes fichiers et à la même version de format ; F-040 à F-042 (`edition/`) ne sont pas concernées. Cette feature se code après la fusion de F-034 et de F-021 ; la conception relit F-038 et F-039 dès que leurs specs existent et signale tout partage du numéro de version du document de table.
  - H12 — Conception requise avant le code (agent-architecte-conception, ADR) : amendement de l'ADR-0016 (version 2, forme stockée de la cellule d'ensemble, couleur d'option, élévation, reconnaissance par l'ancien code) et addendum de l'ADR-0019 si l'écran change de module. Pas de nouvelle dépendance directe attendue : le champ de saisie à liste est écrit par le projet (comme la grille, ADR-0019) ; agent-veille n'intervient que si la conception en propose une.
  - H13 — Le panneau « Options » reste le lieu de renommage, d'ordre et de retrait (F-018-AC22) ; cette feature n'y ajoute que la couleur.
- Prérequis à la charge du dev (fichiers refusés à un agent) : aucun nouveau paquet de workspace ni dépendance directe attendus ; `.dependency-cruiser.cjs` seulement si la conception propose une règle nouvelle ; texte exact fourni par la conception.
