# SPEC F-056 — Coutures laissées par les dérogations de F-008 à F-013 (D-016, D-024)

Statut : brouillon
Tier : standard
Revue : reviewer-frontend, reviewer-backend

- Objectif (une phrase, côté métier) : ce que les dérogations de F-009 et de F-013 ont laissé sans preuve est prouvé par des tests, de sorte qu'une modification de la configuration du serveur ou de l'état de synchronisation ne casse plus en silence un appelant ou un écran.
- Origine : D-016 (F-009 acceptée par dérogation : couture des appelants de `creerApplication` et `lireConfiguration`, variables du service `serveur` de Compose non vérifiées) et D-024 (F-013 acceptée par dérogation : AC41 sans la fermeture 1001 dans un navigateur, AC10 lu par `navigator.onLine`, AC45 sur un membre typé mais absent du README), reprises par la décision du dev du 2026-11-02 « zéro dette ouverte ». Les dérogations elles-mêmes sont closes.
- Vocabulaire : « couture » : test qui énumère les appelants d'une signature ou d'un contrat et échoue si un appelant n'est pas attendu ; « variable du service » : entrée de `environment:` du service `serveur` de `infra/docker-compose.yml`.
- Critères d'acceptation :
  - F-056-AC1 : QUAND un fichier de `apps/server` ou d'`infra` appelle `creerApplication`, LE SYSTÈME DOIT l'avoir dans la liste attendue d'un test de couture, qui échoue sur tout appelant absent de la liste (cas fautif donné comme donnée).
  - F-056-AC2 : QUAND un fichier appelle `lireConfiguration`, LE SYSTÈME DOIT l'avoir dans la liste attendue d'un test de couture de même nature.
  - F-056-AC3 : QUAND `lireConfiguration` lit une variable d'environnement, LE SYSTÈME DOIT la retrouver dans le service `serveur` de `infra/docker-compose.yml` ou dans une liste de variables facultatives du test, et échouer sur toute variable lue mais ni déclarée ni listée.
  - F-056-AC4 : SI une variable déclarée dans le service `serveur` n'est lue par aucun code, ALORS LE SYSTÈME DOIT faire échouer le même test (variable morte).
  - F-056-AC5 : QUAND le serveur ferme une connexion de synchronisation avec le code 1001, LE SYSTÈME DOIT passer le client à l'état de reprise puis le reconnecter, constaté contre le vrai serveur de test de F-013-AC42 ; et un scénario de bout en bout DOIT le constater dans un navigateur réel à travers le relais de développement de Vite (F-013-AC41, qui énumère déjà la lecture du code 1001), joué par le dev ou par la CI de F-052.
  - F-056-AC6 : QUAND le serveur est injoignable alors que `navigator.onLine` vaut `true`, LE SYSTÈME DOIT désactiver l'action « Synchroniser cet espace » avec la raison « Demande une connexion au serveur » (F-013-AC10), l'état étant lu sur la connexion de synchronisation et non sur `navigator.onLine`.
  - F-056-AC7 : QUAND `navigator.onLine` vaut `false` alors que le serveur répond, LE SYSTÈME DOIT garder l'action active (cas inverse du précédent).
  - F-056-AC8 : QUAND un membre est typé dans l'interface publique du module de synchronisation (F-013-AC45), LE SYSTÈME DOIT l'avoir dans le README du module, et un test de couture DOIT échouer sur tout membre typé absent du README.
  - F-056-AC9 : QUAND F-056 est livrée, LE SYSTÈME DOIT laisser chacun des tests de F-009 et de F-013 qu'elle touche sans oracle modifié, hors AC6 et AC7 qui remplacent la lecture de `navigator.onLine` ; ces tests sont nommés dans `MEMORY/features/F-056.md`.
- Hypothèses (recommandation de la planification) :
  - H1 — Variables facultatives de `lireConfiguration` : recommandation, la liste des facultatives vit dans le test, l'inventaire est fait au démarrage.
  - H2 — AC5 en navigateur réel dépend de F-052 pour tourner en CI : recommandation, livrer le test contre le serveur de test (jsdom) maintenant, le scénario Playwright rejoignant le registre de F-052 ; le dev peut le jouer à la main avant la RC1.
  - H3 — D-024 mentionne une « fermeture 1001 » et une lecture de `navigator.onLine` sans nommer les fichiers : recommandation, `grep` du code 1001 et de `navigator.onLine` dans `apps/web/src` et `apps/web/test` pour l'inventaire.
  - H4 — Le périmètre d'agents suit les dossiers : `agent-frontend` (client), `agent-backend` (couture serveur), `agent-devops` (`infra/tests/` pour la couture de Compose).
- Hors périmètre (explicitement) : D-023 (F-049) ; la configuration elle-même (aucune variable n'est ajoutée ni retirée) ; D-002 et D-003 ; les dérogations des autres features.
- Pourquoi ce tier : tests de couture et lecture d'un état déjà exposé, sans module ni dépendance nouveaux : `standard`. Contrat public inchangé ; les appelants sont énumérés (AC1, AC2, AC8).
- Agents : agent-frontend, agent-backend, agent-devops
- Dépend de : rien (le scénario navigateur d'AC5 rejoint le registre de F-052)
